## 二、三条硬教训（用真实渲染定位，写进工具注释）

1. **零厚度板的 `down` 面必须反转 v**。up/down 共面、MC 的 down 面 v 沿 −z，
   不反转会在方块中心渲染出**亮"X"十字**。我为它连续误改 4 轮贴图内容才定位到几何。
2. **外层 uv 的 `v2` 必须是 7**（贴图 y0..7 外层 / y8..15 内层）。写 8 会**采到内层第 1 行**。
3. **贴图要画「稀疏细叶」，不能画「实心宽叶」**。4 片板共用同一 uv 窗口并重复 4 次，
   画实心宽叶会拼成**实心圆盘**；TFC `bird_nest_fern` 俯视是"星芒"就因为它的贴图细而透。
   这点是与 TFC 原版**同角度对比**（`out/DIAG2-inner-vs-outer.png`）才发现的。

**外加两条来自子代理的情报**（purslane 组）：
4. **渲染器 bbox 随贴图 alpha 变化**（内层外端掏空后 age_5 由 5.66 掉到 4.95），
   不是纯几何值，**不能当"几何被改"的证据**。
5. **PowerShell 参数名与局部变量名大小写不敏感**：`[string]$R3` 与局部 `$r3` 是同一变量，
   赋值被类型约束转成字符串，`DrawImage` 报 "Cannot convert System.String"。
   与 AGENTS.md §8.2-1（`$H/$h`）同源。

## 六、基础设施：两条实测结论（独立复核 agave 子代理的发现）

### 1. uv 角点语义 ⇒ 一个 7 行的窗口只覆盖 **7** 行，不是 8 行

`uv = [0,0,16,7]` 是**角点坐标**（矩形 (0,0)–(16,7)），采样 `sy = v1 + (v2−v1)·t`，`t∈[0,1]`
⇒ 实际取到的行只有 **0..6**，**y=7 从不出现**。

**复核方法**：做一张"行号编码贴图"（第 n 行灰度 = n×16），贴到单板 probe 模型上俯视渲染，
再把画面里所有非背景像素的灰度读回来 —— 出现过的行只有 **0..6**，row 7 一个像素都没有。
证据 `out/PROBE-rows-p89.png`。

**结论**：
- **几何不用改**（板长 7 ↔ uv 跨 7 ↔ 采 7 行，本来就是 1:1，正确）。
- 但**贴图口径要改成**：外层有效区 **y0..6**、内层有效区 **y8..14**；**y=7 与 y=15 是死行**。
- 已落盘的 7 个物种在设计时把 y7/y15 当作"叶根行"，**该行实际未生效**；
  但同一设计里 y6/y14 也是叶根内容，所以外观损失轻微（叶根窄一行），**不必回炉**。

### 2. 零厚度板的 up/down 四边形共面 ⇒ 画家算法由浮点决定谁可见

8 片板 `from.y = to.y = 0`，up 与 down 四边形**深度完全相等**，
渲染器的平均深度排序只能靠浮点 ULP 决定先后，**逐板随机**。
而 MC 里朝上的面才是可见的那个（cutout 剔除背面）—— 所以旧预览图可能与实机不完全一致。

**修法（已实施）**：给 down 面一个固定的微小后退（`depth -= 0.01`），保证 up 面永远后画、覆盖 down。
修完用同一张行号 probe 复跑，行 0..6 稳定出现、无异常行。
（另一条并行建议来自 agave 子代理：或把 down 面 uv 改成 TFC 写法 `[16,0,0,16]`。）

### 3. `parent: "block/crop"` 指向 MC 本体

单层作物模型只有一行 `{"parent":"block/crop",...}`，解析为 `minecraft:block/crop`（原版 jar）。
离线渲染器的 assetRoot 只挂本模组 assets + TFC jar，**直接渲染 src 模型会报
`model not found or has no elements` —— 这不是模型丢失**，用 lab 版 wrapper 即可
（`.probe/lab-assets/minecraft/models/block/crop.json` 已备好）。

## 十四、⭐ PK 组的核心发现：TFC 原版作物贴图的实际画法（应作为全项目风格基准）

PK 组（E 组，7 种可采摘作物）在前 6 轮把 chili 画成"蘑菇/圣诞树"，**根因查明**：
> **中央 1 列茎从 y1 贯穿到 y15** + 左右对称的伞状叶冠。

第 7 轮起它改成**导出 TFC 原版作物贴图并放大逐个看清画法**，随后 7 个物种全部立住。它总结出的 TFC 画法三条：

### 1. 叶是「密集不规则连通的叶块」，不是一片片分开的叶
- 叶子必须**成片连通**；孤立 1~2px 的像素在 3D 十字几何下会被渲染成**十字杂点**。
- 叶块**内部留 1px 的洞**是允许的（这正是 TFC 的质感来源）；但**洞留大了就成"门框"**。

### 2. 茎极细：1~2px；且植株「贴底」
- 茎宽 1~2px，不是 4px 的柱子。
- 植株（叶块 + 茎）要**压到贴图底部**，不要悬在半空——TFC 的作物都"站"在方块底面上。

### 3. 体积感用**离散色阶**，不用渐变
- 果实/叶球用 亮/中/暗 三档色阶表现体积（PK 组的茄子 `q/u/v`、辣椒 `t/s/r`）。
- **禁止径向渐变、噪点、球面光照**（用户明令）。

我在第 9~12 轮抽查时反复看到"蘑菇形"（chili / taro / turmeric / millet 的叶冠），
当时只能判断"通用骨架不对"，**却给不出"那该怎么画"**。PK 组给出了可操作的答案：
**不是"叶冠要改形状"，而是"茎要细到 1~2px、叶要连成不规则块、植株要贴底"**。
这三条同时也能解释我自己的对照示范（`REF-CHILI-correct-form.png`）为什么中间还偏实——

## 十五、⭐ 「洞的大小」是硬参数：三次对照实验（第 27 轮）

E 组给出画法第 ① 条时说"叶块内部留 1px 的洞是质感来源，洞留大了就成门框"。
我把这句**定性提醒做成了三次对照实验**（同一物种 turmeric、同一几何、逐像素手写）：

| 版本 | 叶块处理 | read_image 在 3D 里看到的 |
|---|---|---|
| B 组原版 | 两块**分离**的绿块，中央大空隙 | 积木（橙色底座 + 对称绿块） |
| 我的 v2 | 叶块**连通、无洞** | 一个**实心绿块**，完全没有叶面质感 |
| 我的 v3 | 连通 + **一个 2×4 的方洞** | **"门框"** —— 洞大到能看穿，读成建筑构件 |
| **我的 v4** | 连通 + **两个错开的 1px 洞** | **叶面质感** ✅ 正确区间 |

**结论：这不是修辞，是必须严格遵守的具体尺寸。**

我**两次都走到了极端**（v2 无洞、v3 过大），第三次才落在正确区间 ——
说明"1px"这个数字需要被当成硬参数对待，而不是"留点洞就行"。

### 17.3 ⭐ 第一版做法被视觉复核否掉（教训：**不许只量化**）

第一版是「**水平缩放 + 竖直错位**」：按 `sf ∈ {0.55…1.6}` 把左右半边各自拉伸/压缩。
量化指标很漂亮（asym 平均 24.4 / 37.3），但 `px/DESYM-CMP.png` 一看就废：

- `lupin_5` 的蓝色花穗被拉成**一块平板**（横向 `sf=1.6` 把中央 1 列复制出去）；
- `kale_rosette_3` / `cauliflower_leafball_3` / `quinoa_5_bottom` 叶块里出现**大暗洞**；
- `agave_rosette_2` 的细长叶片被**切碎成片段**。

**根因**：水平重采样会把**源的透明像素搬进叶块内部**——这是 inverse map 的固有副作用，
量化指标（asym / opaque / 色数）**一条都看不出来**。

**改成不产生空洞的两招**（现版）：

1. **左右两半各自做「按行带、外强内弱」的竖直错位**（`w = (k/7)^0.5`，中央茎列 x=7/8 恒为 0）
   —— 列内整体位移，**不可能留洞**；左右各自一条「限幅随机游走」（相邻带最多差 1），是自然的弯不是撕裂。
2. **每行按行带对左/右外缘做 ±1px 外扩或内收** —— 只动轮廓，不碰内部结构。

全程**只搬运原始像素，不引入任何新颜色** ⇒ 调色板、离散色阶、TFC 风格完整保留。
第二版视觉复核（`px/DESYM-CMP2.png`、`px/DESYM-LANDED.png`）：
内部结构、1px 质感洞、白中肋、花穗、芽尖全部保留，只多了自然的不规则。

## 十八、⭐ 用「同一渲染器并排校准」定位到真正的质量差距（第 32 轮）

§十七 解决了「对称」这条系统性问题，但 Lead 手工重画 `eggplant / shallot / artichoke / turnip`
时连续 3 轮都判自己不合格，于是做了一次**校准实验**：

> 把 **TFC 原版作物贴图**（`.probe/ref-tfc/` 里 jar 原样导出的 339 张）
> 和**我方贴图**，用**同一个 `render-tfc.ps1`、同一套 lab wrapper、同一角度 p28** 渲染并排。
> 产物：`px/CALIB-TFC-vs-OURS.png`（12 组对照）。

### 结论（一句话）

> **TFC 原版是「高频细节」，我方是「低频色块」。**
> TFC 的 16×16 里塞满 **1px 级别的错落色阶和逐像素不规则的轮廓**；
> 我方是大片纯色、边缘平滑，一眼过去就是几个大色块。

这一条解释了为什么"形状明明画对了"却总觉得不像 —— **差距不在轮廓，在细节密度**。

### 由校准直接纠正的两个误判

1. **我差点把「下方基部 + 上方叶冠」当成"蘑菇"重画掉。**
   校准图里 **TFC `beet_5` 就是「下方红色根块 + 上方绿色叶冠」**，
   `turnip` 的"白球根 + 绿叶"与它同构 ⇒ **结构本来是对的，不该动结构**。
2. **TFC 原版在 p28 下本身就很"稀疏、窄小"**（`onion_5`、`carrot_5` 尤其），
   并不占满画面。此前我按"要占满 16×16"去改，方向是错的 ——
   正确目标是**细节密度**（同一株上用多少种色阶、轮廓有多少 1px 起伏），不是**覆盖率**。

### 落地的新判据（已写进 `AGENTS.md`）

- 一株植物用掉 **60~170** 个不透明像素，其中**至少 1/3 是不同色阶**（不是同一号绿）。
- 外轮廓**逐像素不规则**，不要出现 3px 以上的直线边。
- 内部用 **1px 错位洞**做质感；**洞留大了就是"门框"**（`px/TURMERIC-4versions.png` 三次对照）。
- 体积感一律**离散色阶 ≥3 档**，禁止径向渐变 / 噪点 / 球面光照。

### 24.3 「噪点」与「TFC 质感」的区别

1. **2px 宽**，用两档色交替表现原型的「**纵沟**（grooved）」。
2. **从基部分枝、向外张开** —— 两根平行直下不像披散；两根贴太近又变成"一根粗柱"。
3. **不能光秃** —— 叶沿茎互生，下部茎干也要有小叶。
4. ⚠️ 注意区分：**「同一列连续 ≥5px 会被渲染成柱子」对茎不适用**——
   TFC `wheat_7`/`sugarcane_*` 的茎秆本来就贯穿全高（同列连中位 10 / P90 16），那是正常的。

### 26.10 茎干 36~37：**用户指出「向内倾斜很奇怪」——我把 V 形画反了**

| 轮 | 改动 | 结果 |
|---|---|---|
| 34/35 | 误把「披散」理解成"地面处张开" ⇒ **地面最宽、往上靠拢** | 读成**倒 V / 三脚架**，用户当场指出「向内倾斜很奇怪」 |
| 36 | 把方向倒过来：**基部收拢、向上张开** | 方向对了，但两根茎在底部**合并成一块** ⇒ 最大同色块 7%→**14%** |
| **37 ★** | 方向保持修正，且两根茎**一直保持分离**到地面，只在两侧出根 | **最大同色块回到 10px (7%)**，同色块 79 = TFC beet_5 |

> **规则**：**植株分枝必须「基部收拢 → 向上张开」**。
> 反过来（地面宽、往上收）会读成倒 V / 三脚架 / 无根之木。
> 这条与"茎要贴在地面上"不矛盾：**收拢的是基部，张开的是上端。**

`fenugreek_5` 最终（微调37）：op 143 · 6 色 · LUM 110.5 · asym 43 · 同色块 79 · 最大同色块 10px(7%)
—— 六项全部追平或优于 TFC `beet_5`。

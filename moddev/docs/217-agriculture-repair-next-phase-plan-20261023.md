## 三、范围与保护边界

### 本阶段包含

1. A（`tfcfarmingplus`）现有普通作物、可采摘作物、水田作物、攀爬/双格作物、莲座/叶球、灌木、野生作物、果树、结果枝和坚果的内容闭环核查。
2. 与作物直接相关的注册、种子/树苗、方块状态、气候/养分、成熟与采收、掉落、食品/材料属性、腐烂、标签、世界生成、模型/贴图、JEI、Patchouli 和语言。
3. A 与 B、TFC、Firmalife 之间农业原料和产物的命名空间及引用闭合检查。
4. 按现有证据修复明确失效的作物代码、数据和资源；为需要玩家操作才能证明的项目准备清晰的实机验证清单。

### 本阶段不包含

- 新增一批作物、新建温室/灌溉/地窖或另造 TFC 已有的连作、适播、授粉等机制。
- 继续扩展厨具、木工、养蚕或其他 B 模组系统；不把近期烤炉问题并入农业修复。
- 未经台账和备份就删除已注册方块/物品，或以注销注册处理显示问题。
- 通过批量生成覆盖已认可的手绘贴图；如发现美术缺口，先列出对象、原图、模型引用和影响，再按 `INBOX.md` 的逐图检查流程处理。
- 直接照抄示例模组、教程、反编译业务代码或生成器逻辑。只允许核对公开 API/数据格式，业务行为由本项目独立设计；TFC Woodworking 的既有例外不适用于农业。

## 四、必须持续遵守的用户决定

### 草莓

- 禁止草莓灌木自然生成；保留 `tfc:plant/strawberry_bush` 注册和旧存档读取能力。
- 原版草莓灌木从创造模式物品栏、JEI 和 Patchouli 中隐藏；不能误隐藏 TFC 草莓果实、项目普通草莓作物、项目野生草莓或种子。
- 项目普通草莓与野生草莓仍可种植/生长/采收，果实使用 `tfc:food/strawberry`；种子逻辑保留。
- 用户此前反馈草莓主要流程基本符合预期，本阶段先做只读回归核对；没有复现证据时不重写该链。

### 可可

- 种植、树体生长和采收继续沿用 `cupuacu`（大花可可树）实现；不得因整理加工链而换成另一套树。
- 施工前从当前源码确认准确注册 ID、树枝/树叶/果实链及实际掉落，不凭历史中文称呼推断注册名。
- 可可豆和基础加工物品使用 Firmalife 原版 ID；保留发酵流程并核实其输入、发酵状态和后续产物能接回 Firmalife 链。
- 用户此前反馈可可主流程基本符合预期；本阶段保护正常主路径，只有台账发现明确断链或回归才修改。

### 农业规则

- 复用 TFC 已有的作物、历法、气候、养分、肥料、标签、食品和腐烂机制；先证明缺口，再决定是否需要项目代码。
- 连作、适播等 TFC 已有能力不另造一套；不得把旧方案中已作废的功能恢复进本阶段。
- 新物种只有在完整闭环要求明确且用户批准新增范围后才排期；当前优先修复已有内容。

## 五、分阶段工作计划

### AR0：农业现状基线与缺口台账（已完成）

**目标：** 建立当前源码事实，识别“真正待修”“已经修好但缺复测”“仅为旧日志问题”和“需求本身未完成”四种情况。

**工作项：**

1. 锁定实际开发目录、A/B 源码目录、当前整合包版本与关键依赖版本；记录构建产物、部署副本和 SHA-256，确认审计对象没有落到重复工程目录。
2. 重新统计当前 A 的植物、作物形态、产物、注册项和资源量，不沿用 117/70 的旧数量作为现状。
3. 为每种现有农业内容建立矩阵：注册 ID → 种子/树苗 → 可放置/支撑条件 → 气候/养分 → 生长状态 → 成熟判据 → 收获与副产物 → 食品/材料数据 → 用途 → 标签/配方 → 模型/贴图/语言 → JEI/Patchouli → 世界生成 → 旧注册兼容。
4. 把 71、93、99、116、120～125、154、188 等记录中的问题逐条回看当前源码与资源；历史记录没有当前证据的统一标记“待复核”，不直接列为已确认缺陷。
5. 检查资源生成器、手工资源与实际构建输入的关系：找出可能覆盖手绘资产的脚本、重复产出目录、废弃清单和 dry-run 不足；每个文件确认唯一权威来源。
6. 输出分级缺口表：P0（崩溃/加载失败/注册或数据损坏）、P1（种植、生长、收获或存档闭环失效）、P2（产物用途、说明或显示不完整）、P3（仅视觉打磨/长线扩展）。每条都附证据、复现方式、风险和建议切片。

**出口条件：** 台账覆盖 A 农业规模、草莓/可可保护项和已发现缺口；每条缺口有当前证据状态和下一步；确定首个修复切片。AR0 本身不修改功能代码。出口记录见 218 号文档。

### AR1：优先修复阻断种植闭环的作物切片

**目标：** 先修 AR0 中最高等级的真实阻断项，每次选择一个形态/同一根因，完成一条能独立验收的垂直切片。

每个切片按以下顺序核查：

1. 方块和物品注册、blockstate 属性组合及实体/方块绑定。
2. 可种植地面、支撑和放置条件；TFC 气候、水合、土壤养分、历法及温度 API 的当前版本语义。
3. 生长计时器播种、服务端状态更新、上下半块/附着方块同步、季节休眠与恢复。
4. 成熟状态、采收交互、掉落表、种子返还、工具行为和多方块破坏处理。
5. 重进世界/区块卸载后的状态延续，以及旧 ID/旧方块实体兼容。

**形态顺序由 AR0 证据决定**；候选分组为：单格与可采摘作物、水田、攀爬与双格、莲座与叶球、灌木与野生作物、果树与结果枝、坚果。不得为了顺序方便把不同状态机强行合并成同一改动。

### AR2：农业产物、土壤养分与加工可达性

**目标：** 解决收获物无法进入 TFC 既有循环或成为无用途库存的问题。

- 对照 TFC/当前整合包真实数据检查食物、种子、纤维、油料、堆肥与其他材料的组件和标签。
- 检查主产品、副产品的产量、工具损耗、腐烂期限和可达用途；分清“没有用途”与“用途存在但 JEI/手册未说明”。
- 复核 N/P/K 消耗和恢复是否遵守 TFC 农田边界、堆肥与肥料标签；不建立重复的养分系统。
- 优先补数据配方和标签，只有数据方式不足以表达且公开 API 已核实时才增加 Java 行为。
- 使用图检/静态表检查输入是否可获得、输出是否可到达、是否有重复或孤儿配方，并人工核对代表性完整链。

### AR3：果树、灌木、野生作物与世界生成

**目标：** 让自然出现、人工种植、附着生长和采收规则一致且不会破坏旧区块。

- 按树种检查树干、枝干、叶片、BE 的宿主/树根位置、季节生命周期、成熟结果、采摘冷却、掉落及生长计时器。
- 检查野生作物/灌木的生成入口、biome/tag/feature 引用、掉落和玩家种植闭环；仅为明确允许自然出现的物种接入生成。
- 对草莓灌木执行专门保护检查：注册保留、生成关闭、三处显示隐藏、项目草莓可种可收。
- 对 `cupuacu` 大花可可树执行专门保护检查：树体机制不变，产物接 Firmalife 原版可可豆，发酵链保留。
- 所有删除或迁移都先列旧 ID、世界引用、替代 ID 和回滚方案；不得用新存档测试结果代替旧区块兼容判断。

### AR4：模型、美术、JEI 与手册一致性收口

**目标：** 把实际玩法状态完整呈现，避免“方块可用但渲染错误”或“手册/JEI 指向不存在的内容”。

- 按方块状态空间逐项核对 blockstate 变体和模型，不仅检查文件存在；包括 mature/fruiting/dormant/dead、上下半块、朝向与 stage 的组合。
- 交叉核对模型贴图引用、PNG 文件、注册物品模型、掉落表、语言、创造标签页、JEI 和 Patchouli。
- 读取 INBOX 中仍在记录的莲座、叶球、双段作物、果树贴图等历史问题；逐项确认是否已被后续实机或资源修订解决，再决定是否重绘。
- 任何贴图重绘先做单物种预览和人工放大检查；没有用户验收的既有手绘资产不得被生成器覆盖。
- 手册只描述当前行为和可执行路径，移除已废弃的温度、季节或配方说明前先核实实际代码。

### AR5：验证、交付与后续闭环

**目标：** 让农业修复结果可重复检查、可回滚，并明确哪些项目仍需用户实机操作。

- 每个切片执行对应的源码/资源门禁、JSON 解析、ID/标签/配方闭合和构建；门禁失败时必须定位并修复，不得把脚本异常当通过。
- 对修改过的生成器先 dry-run 对照文件清单，再备份、生成、差异检查；用户认可资源需证明哈希未被意外改写。
- 构建后比对产物与部署副本的 SHA-256；不在本阶段擅自生成或迁移新的 PCL 整合包。
- 生成用户实机清单，逐项写明世界准备、物品/坐标前置、操作步骤、成功现象、失败时需提供的日志/截图。只有用户实机确认才标记 L4 通过。
- 收尾记录代码/资源变更、验证层级、未解决问题、备份位置和下一片入口；不把待测功能写成“正常”。

## 六、优先级和首个修复切片选择

AR0 后使用以下排序确定首个施工项：

1. 会导致启动失败、数据加载失败、区块/存档损坏或物品丢失的 P0。
2. 导致一类作物无法放置、生长、成熟或收获的 P1；优先修复能解释多个物种共同异常的根因。
3. 造成收获物无用途或循环无法完成的 P1/P2。
4. 仅涉及手册、JEI、模型和贴图的 P2/P3，且不得覆盖用户已确认正常内容。

若 AR0 发现 154 号总审计中的 P0 草莓/可可重复注册等问题已被后续源码和实机结果解决，则把它们保留为回归保护，不重新施工。若发现当前代码与后续用户实机确认冲突，先以用户实机记录为基线，做最小复现后再选切片。

## 七、每个切片的完成判据

一个农业切片只有同时满足下列条件才可关闭：

1. 需求、实际根因、输入输出、受影响物种/形态、旧存档影响和回滚点均已记录。
2. 修改遵守独立实现规则；依赖 TFC 的部分只调用当前版本已确认的公开 API/数据格式。
3. 注册、状态、资源、标签、掉落、配方、JEI、Patchouli 和模型引用无断链；必要时对旧 ID 做兼容。
4. 自动门禁和构建证据可复现，构建/部署文件哈希一致。
5. 实机项明确标为“用户已通过 / 失败 / 待验证 / 跳过”；没有用户实际操作证据时不得标成实机通过。
6. 每完成一批，就更新本计划的状态或新增施工记录和手动验收清单。

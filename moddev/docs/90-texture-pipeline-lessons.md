## 一、五条可复用规律（每条都有独立验证）

### 规律 1 · `transplant.ps1` 的调色板排序 = 颜色的面积分布 ★★★

`transplant` 按参考图每个像素的**亮度排名**线性映射到调色板各档（暗→暗）。
**因此「把某色放在第 N 档」就等于「让第 N 档亮度的所有像素都变成该色」。**

| 案例 | 错误做法 | 现象 | 正确做法 |
|---|---|---|---|
| 第 22 轮 `chive` | 韭菜花的淡紫放**最亮档** | TFC `garlic` 最亮像素在每根叶顶端 ⇒ 幼苗期冒出"浅紫色方块" | 去掉杂色，纯绿 |
| 第 22 轮 `perilla` | 紫红放两个较亮档 | 紫红占 3/4 ⇒ age4 成"紫色地毯"；改亮粉后又成"开粉花的灌木" | **暗紫红只占中间 1 档** |
| 第 24 轮 `buckwheat` | 红褐放第 4 档 | 红褐占 1/3 ⇒ 像"枯草花斑" | **红放最暗档** ⇒ 只在茎 |
| 第 30 轮 `ginger` | 根茎色 `k=9A7A3A`(LUM124) 放第 4 档 | **满图褐色斑点**（像斑点狗） | `k=4A2A10`(LUM47) **最暗档** ⇒ 只在茎干 |
| 第 32 轮 `rhubarb` | 红 `r=C03A2A`(LUM85) 放第 2 档 | 1/3 像素是红 ⇒ 像"红绿格子布" | `r=7A1A10` **最暗档** ⇒ 只在叶柄 |

> **操作规矩**：① 异色器官（花/果/根/荚）**只占 1 个档**；
> ② 主色（叶）占两端各 1 档 + 中间 1 档；③ 异色插在**中间或最暗**，**不要放最亮档**
> （红/橙/紫天然亮度低，放最亮档会导致排序不稳）。

### 规律 2 · 苗期语法 ≠ 成熟期语法 ★★★

| | 苗期 age0~2 | 成熟期 age3+ |
|---|---|---|
| TFC 实测 | **1px 宽的离散细芽/点阵**：`rice_0` 只有 2 行 5 个 1px 芽；`cabbage_0` 只有 **3 个像素**；`beet_1` 是水平散布的点阵 | **实心叶块 + 逐像素不规则交错**：`rice_5` 每行 8~17px、20+ 档色阶 |
| 我犯过的错 | 画成 2×2 以上实心块 ⇒ **"三块石头"** | 套用苗期 1px 轮廓线 ⇒ **空心方块 / 十字 / 田字**；色阶规则交替 ⇒ **棋盘格** |

**中间年龄也要照 TFC 中间期骨架移植**，否则 age2→age3 会出现断崖
（本会话曾出现 3.7 倍跳变，TFC 同族只有 1.24 倍）。

### 规律 4 · 方块贴图（`_head` / `_side` / `_fruit`）必须**全铺满**，参考要 op ≥ 100 ★★

- 这类贴图是**中心立方体六面共享**或方块侧面 ⇒ **`opaque` 必须 = 256**，
  移植后要把所有 `.` 填成背景色。
- **参考必须选 `op ≥ 100` 的密集贴图**：第 27 轮 `cardoon_rosette_fruit` 用 `cabbage_5`（只有 45px），
  填满后 **90% 是纯深绿**、只剩中央一小块 ✗ ⇒ 改用 `beet_5`(116)。
- `peanut_5`(158) 的细碎小叶 + 填满 ⇒ 有"色块阵列"感；`beet_5` 的叶丛更有机。

### 规律 5 · `soybean` 骨架的 `_3~5` 几乎不生长，必须主动拉密度 ★

`soybean` 的 `3/4/5` 档是 46/49/50（结荚期缓慢）⇒ 用它派生出的物种**后期看不出生长**。
**两次踩到**（第 26 轮 `brussels_sprouts`、第 31 轮 `bambara_nut`）。
处理：给 `_5`（或 `_3~5`）做 `overlay` 加密。

## 二、工具链（`.probe/texture-design/`）

| 工具 | 作用 | 关键用法 |
|---|---|---|
| `transplant.ps1` | **把 TFC 参考图的逐像素形状映射到本物种调色板**（本会话的主力） | `-Ref <tfc png> -Palette 'B=..,d=..' -Out <design txt>` |
| `shrink.ps1` | 骨架重塑：`-Top N` 清空内容顶部 N 行（**底部不动**）、`-Side N` 每行去掉最外 N 个不透明像素 | ⚠️ **稀疏图禁用 `-Side`**（每行只有 1~2px 时 = 删掉整行） |
| `overlay.ps1` | 自身错位叠加（加密 / 打破镜像对称 / 加宽） | `-Base x -Add x -ShiftX 3 -Out x` |
| `contact.ps1` | 分页接触表（30/页，格子 + 文件名标签）—— **验收的唯一入口** | `-Dir <src> -Filter '*.png' -PerPage 30 -Out px/CT.png` |
| `lab-render.ps1` | 2D 放大 + 3D 预览（自动维护 lab wrapper） | `-Name a_5,b_5 -Pitch 28 -Mode 3d` |
| `seam-audit.ps1` | 双段作物接缝全量审计 / `-Fix` | ⚠️ **`-Fix` 只改 PNG，不改设计稿** |
| `audit-all.ps1` | 尺寸 / opaque / 色数 / LUM / asym 总审计 | |
| `draw2.ps1` | 自包含设计稿 → PNG（自动打印指标） | |

## 三、设计稿格式规范与三个坑

**标准格式**：首部 `key=RRGGBB` 调色板 + **恰好 16 行 × 16 字符**像素表，`.` = 透明。

**⚠️ 本会话发现三种并存格式**：
1. `CHILI-5.txt`（大写连字符，自包含）✓
2. `sesame_3.txt`（小写下划线，自包含）✓
3. **旧格式**（`loofah_7_bottom.txt` / `snake_gourd_7_bottom.txt`）：
   **无调色板行 + 用空格分组**（`.... .... .cc. ....`），
   甚至引用外部调色板（`# palette sesame_c`）+ 镜像对称约束的产物。
   ⇒ **不能被 `overlay.ps1` 处理，必须先"从 PNG 反向重建自包含设计稿"**。

**反向重建的两条铁律**：
- **双段贴图（`_bottom`/`_top`）必须共用同一调色板映射**，否则接缝行字符含义不同 ⇒ 接缝必错。
- 重建后再 `Sync-Seam`（`_top` 第 15 行 := `_bottom` 第 0 行），并跑 `seam-audit` 复验。
  本项目当前 **72 对齐 / 0 错位**。

## 四、系统性废稿的识别模式 ★

**同一个生成器会刷出整族同形废稿**，识别出"模式"比逐张修更高效：

| 模式 | 受害范围 | 特征 | 统一修法 |
|---|---|---|---|
| `_head` 马赛克 | 叶球类 **6 个物种** | 底色 + **规则排列**的方块阵列 | `beet_5`/`peanut_5` 移植 + 填满 |
| `_fruit` 马赛克 | 莲座类 **4 个物种** | 模糊色块 | 同上 |
| 苗期"三块石头" | 水生 9 物种 | 2×2~3×3 实心方块 | TFC 中间期骨架移植 |
| 成熟期"几何体" | 多物种 | 空心方块 / 十字 / 田字 / 对称圣诞树 | TFC 成熟期骨架移植 |
| "蘑菇/伞盖" | `rhubarb` · `artichoke` · `taro` | 圆冠 + 细茎 | 移植 + 重塑 |

## 五、已知差距（唯一一项，留待精修）

**加密过的成熟期叶块比 TFC 偏粗偏密** —— `overlay` 加密的副作用。
3D 并排（`px/CALIB-3D-OURS-vs-TFC.png`，同模型同相机）可见：
`chive_5` 的叶比 TFC `garlic_4` 粗、`rhubarb_5` 的红底比 `beet_5` 散。

**精修方向**：改用**"逐像素补几根细芽"**而不是整体 `overlay`。
涉及物种 ≈ `chili` · `eggplant` · `sesame` · `lotus` · `winter_melon` · `loofah` ·
`snake_gourd` · `leafball` 的 1~2 档。

**注意**：`overlay` 会打破单调性（`loofah` 出现过 `_5`(204) > `_6`(156) 的反超），
**每次加密后必须重跑单调性核验**。

## 六、复现流程（下轮/后继会话直接照做）

```
① dump TFC 同族骨架        dump-ref.ps1（确立行语法与密度曲线）
② 查"已用参考对照表"        避免与其它物种撞骨架（§一 规律 3）
③ transplant 到物种调色板   调色板按"异色只占 1 档"设计（§一 规律 1）
④ 接触表 + read_image       逐张写下"我看到了什么"（判据 0）
⑤ 不合格 → 改 → 重看        眼睛优先于任何指标
⑥ 3D 复核                  lab-render.ps1 -Pitch 28 -Mode 3d
⑦ 双段跑 seam-audit        设计稿也要同步，否则下次重渲染又会错
⑧ 全量单调性核验            任何加密/裁剪后都要重跑
⑨ audit-all + verify.ps1   交付前必跑
```

**判据 0 的实操含义**：`op / 色数 / LUM / asym` **只是"是否值得再看一眼"的提示**，
永远不能用来宣布"改好了"。本会话 4 次调色板迭代、5 次苗期重画，
**每一次的"不合格"都是 `read_image` 看出来的，没有一次是指标发现的**。

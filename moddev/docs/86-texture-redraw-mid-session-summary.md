## 四、⭐ 最有价值的产出：TFC 作物贴图的画法（E 组实测得出）

> chili 画废 6 轮的根因 = **中央 1 列茎从 y1 贯穿到 y15 + 左右对称伞状叶冠 = "蘑菇/圣诞树"**。

**三条画法**（已写入 AGENTS.md 顶部，全项目风格基准）：
1. **叶要"密集不规则连通成块"** —— 孤立 1~2px 像素在十字几何下渲染成**十字杂点**；
   叶块内部留 **1px** 的洞是 TFC 的质感来源，**洞留大了就成"门框"**。
2. **茎只有 1~2px 宽**，植株要**压到贴图底部**。
3. 体积感用**离散色阶**（亮/中/暗），禁止径向渐变/噪点/球面光照。

参考图：`px/_REF-tfc-crops-zoom16.png`、`_REF-tfc-fruitcrops-zoom16.png`、`_REF-tfc-bushcrops-zoom16.png`。

**Lead 另备三份"正确形态"对照基准**（同尺寸同几何、逐像素手写）：
`px/REF-BUCKWHEAT-correct-form.png`（荞麦=红褐茎+白花簇，不是穗）、
`px/REF-TARO-correct-form.png`（芋头无地上茎，叶柄放射）、
`px/REF-CHILI-correct-form.png`（辣椒=Y 形分叉灌木+垂果）。

## 五、已知偏差与待办（诚实清单）

### 需用户裁决
- **`napa_cabbage` LUM 150.4 > 140**：白色菜帮是识别特征，压进区间会失去特征。
  **Lead 取值：贴近原型优先**，请用户确认。

### 已接受（记录在案，不返工）
- 各物种**幼苗阶段 opaque 14~54**（低于 60）：十字几何每 age 相同，生长递进只能靠贴图；画大就破坏递进。
- `chive_0`/`okra_3`/`rhubarb_3`/`artichoke_3` **色数=3**（4/42≈9.5%）。
- `cardoon` **色数=3**、莲座/叶球家族 6 个 age 贴图相同（**生长由几何表达**，设计如此）。

### 改进项（不阻塞）
- **B1 chili**：蘑菇形 → 用 `REF-CHILI-correct-form.png` 的分叉灌木骨架。
- **B2 taro**：改"球茎 + 叶柄放射 + 盾形叶"，用 `REF-TARO-correct-form.png`。
- **B3 turmeric/ginger**：叶应是长披针形；Lead 已重画一版示范（`px/TURMERIC-old-vs-new.png`），
  但**叶块未留 1px 洞**，还差一步。
- **B4 millet**：bottom 的"X 形蝴蝶结"叶片打散角度。
- **B5 spread 3 种**：Lead 已重画去重（`px/SPREAD-VINES-v2.png`），已落盘。
- **B6**：单层/双季作物的 bottom 叶簇仍偏通用。

### 收尾前必做
1. **C/F/G 三组报告落盘 + Lead 逐物种看图复验**（按 §四 三条画法判）；
2. 重跑 `accept-all.ps1`，看 avgColors →≈5、avgLUM →110~140 的收敛；
3. **`gradle clean build` + 实机复核** —— 落盘量约 300+ 张，**未过实机不能算验收**；
   （B 组指出：本次未删除任何资源文件，理论上 `gradle build` 即可，但替换量很大，建议 `clean build` 保险）
4. `verify.ps1` 那 **4 条预先存在的空名贴图警告**值得单独查一次（已 A/B 确认非本次引入）。

## 六、基础设施修复（本轮顺带完成，影响所有后续视觉工作）

| 修复 | 影响 |
|---|---|
| 渲染器 6 个面顶点顺序（左下→**左上**） | 修前 **4 个竖直面 + down 面 V 轴全翻转**，所有竖直面预览上下颠倒 |
| 渲染器支持 `tintindex` | 修前 TFC 灰度贴图被渲染成**灰白**，被误当"TFC 风格参考"（用户当场识破） |
| 渲染器 down 面深度后退 | 零厚度板 up/down 共面，画家算法随浮点决定谁可见 |
| UV 角点语义实测 | `[0,0,16,7]` 只覆盖 **7 行**（y0~6），**y7/y15 是死行** |
| 权威参考资产 `.probe/ref-tfc/` | 自包含、可 SHA256 核对、支持 tint/face.rotation/bbox 审计 |

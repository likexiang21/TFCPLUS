# AR3-F 灌木计时与自然生成兼容交接（2026-10-24）

## 一、状态与范围

本批处理12种现有灌木：越橘、熊果、岩高兰、山蓝莓四种矮丛；黑加仑、红加仑、蓝靛果、枸杞、唐棣、野樱莓、茶树、咖啡树八种蔓生主丛及对应八种枝段。共20个活体方块。不是另外新增一组高灌木或物种。

已完成本批源码/资源修复、静态核对、离线构建及部署；没有启动Minecraft、执行模拟刻或新增单元测试。正常种植、实际自然生成、跨季重载和画面均待用户实机确认。预估与实际复杂度均很高（5/5）。用户要求的变量/文件命名与目录结构整理仍按233号计划留到现有工作完成后，本批没有提前开展全局改名。

## 二、证据与根因

### 1. 整表替换漏掉项目灌木并覆盖邻居

活动data/tfc/tags/worldgen/placed_feature/feature/berry_bushes.json原为replace:true，枚举10个TFC和2个Firmalife生成项来排除草莓，却没有12个项目灌木patch。这会使项目灌木的四件生成数据虽然存在，却不从该生成标签进入世界，也覆盖其他模组向该标签追加的内容。不是缺少模型或方块注册。

当前NeoForge构建21.1.233与客户端运行时21.1.248均有TagFile.remove和TagLoader移除成员语义。已读取本地补丁和运行时字节码确认，不依赖猜测。保存证据为TagFile.java.patch、TagLoader.java.patch、runtime-tag-api.txt。remove成员在运行时按可选项处理，移除不存在成员不会因为必需引用而创建非法持有者。

### 2. 蔓生玩家放置缺少项目计时重置

矮丛已有setPlacedBy→afterPlace；蔓生主丛只有采收补充，没有放置重置。父类SeasonalPlantBlock调用的BerryBushBlockEntity.reset按TFC原生类型查表，不命中项目BE，留下Integer.MIN_VALUE哨兵值。原生随机刻又直接进入tick，可能把哨兵差值当成极长生长时间。

自然生成和旧记录也可能保留未初始化时间；自然生成的上层主丛/枝段默认根位置为自身，若没有正确继承，需要在原生气候检查前恢复可确定的同种根关系。

### 3. 原生蔓延交接可以复用

已核当前TFC4.2.11的方法签名和字节码。原生placeNewBushAndResetCounters对来源、新株使用instanceof检查，直接调用实例resetCounter、increaseCounter、setGrowthsRemaining、setStemPos。该链不是按TFC类型查表的静态helper，不能把它也误判为失效后照搬重写。保留原生传播、周期、有限生长预算和最大高度。

### 4. 手册缺操作说明，地下水被写成降水

既有灌木条目列栖息地和物候，但缺统一种植/采收/冷却/回收说明；生成过滤器min_groundwater/max_groundwater却标成降水。此处修正显示，不改变气候数值。茶叶与咖啡豆已有可食用食品定义，饮品用途按70/117号历史计划仍未开发；本批不编造饮品配方或宣称饮品已闭环。

## 三、独立设计及修改清单

### 四份Java

- MySpreadingBushBlock：新增正常放置后afterPlace实例计时初始化；再执行根准备。
- MyBerryBushBlock、MySpreadingBushBlock、MySpreadingCaneBlock：在原生randomTick之前准备计时和根，并在public tick入口准备，覆盖直接scheduled更新。其余生长和采收委托父类。
- MySeasonalPlantFix：新增prepareBush和受限findBushRoot。客户端或无项目期望实体时直接返回；只有lastUpdateTick等于哨兵值才resetCounter，保留已经有效的年龄、lastPickedTick和growthsRemaining。

根恢复只处理stemPos等于自身的情况，最多32步：枝段按FACING反向找到其配对主丛；主丛只沿同一方块物种向下；接到已明确记录的来源根或允许生长的原生地面才采用。每步先用Level.isLoaded核对区块及高度，不强制加载。显式非自身根不重写，支撑缺失、跨未加载区块、物种不匹配或达到上限则保持原记录。

不新增NBT字段，不重置全部旧株，不给自然株补虚构的多年年龄。原生后续阶段/季节、气候、预算、随机蔓延及高度均沿用。共享helper原有afterUse/afterPlace逻辑不变；果树叶片没有调用新prepareBush，保护前几批果树修复。

### 五份游戏资源

- berry_bushes标签改为replace:false，仅追加12个项目patch；remove只列tfc:plant/strawberry_bush_patch。原版草莓灌木仍注册，创造/JEI/手册隐藏和项目草莓规范产物不变。旧世界已有灌木不被清除。
- 中英文bushes、bushes_high四文件：共28个文字页（4简介＋24物种页），加入统一操作说明，将栖息地标签改为地下水。原12/20页数量、日历和空页配对、图示、锚点及跳转保持。

没有改变食物营养/腐烂、掉落表、PNG、模型、blockstate、物候数组、生成概率或ID。原生锋利工具回收及蔓生幼株概率、枝段木棍掉落保留。死灌木/死枝段沿用本项目既有不绑计数实体的实现，不会自动老化消失；本批未把这一既有差异改写为原生行为。

### 工具

修改gen-wild-injection、gen-dead-and-wild-bushes：只允许隔离输出目录，防止旧硬编码路径或默认活动输出破坏资源；两者均保留定向移除草莓。gen-wild-injection还按可可策略排除旧cocoa，避免重新注入旧树。gen-dead-and-wild-bushes仅修约束和标签模板，因其还含旧作物/模型输出，本批未全量运行。

修改gen-patchouli-book同步文字；新增只读audit-bush-contracts，接入既有verify。5个新/改PS工具均保留UTF-8 BOM，执行前解析；最终灌木检查也在Windows PowerShell下通过。

所有生成只在moddev/.probe/generator-output/ar3f-*-20261024草稿运行，书只选择文字字段；三个注入标签的成员集合与活动资源对照一致，旧cocoa未回填，87项野生作物和48项有效果树注入保留。没有发布草稿的占位美术或全量清单。

# K1 厨具系统实机测试清单与自动化验证记录

日期：2026-10-18  
范围：K1 厨房家具骨架（橱柜台面、半高柜、水槽柜、香料架、食品展示柜、果盘）  
目标：在不依赖 TFC Woodworking 的前提下，确认注册、资源、JEI、容器交互、保存和破坏掉落。

## 一、测试前提

- 使用工作区部署包：`mods/TFCAgriculturePlus-NeoForge-1.21.1-0.1.0.jar`。
- 启动脚本：`moddev/tools/launch-client.ps1`。
- 默认验证实例使用工作区自带 Java 21 和 `.tooling/game` 运行时。
- 本轮不启用 TFC Woodworking；木工独立性只作为加载条件记录，不把 K1 结果与该模组绑定。
- 自动化测试只负责启动、读日志和获取客户端窗口；真正的鼠标点击、拖拽和 JEI 画面确认必须在客户端保持运行后进行。

## 二、逐项实机清单

- [ ] A01：客户端能启动并保持到主菜单。

### B. 创造栏、JEI 和手册

- [ ] B01：六类家具都出现在创造模式物品栏，且每类至少检查一项 TFC 木材和一项 AFC 木材。

### C. 放置与外观

### 追加诊断启动（14:13）

为确认退出点，使用 `launch-client.ps1 -QuickPlay '' -Wait` 捕获一次带等待的启动过程。该次日志继续推进到以下阶段：

- `Client resource reload complete!`
- 纹理图集全部创建完成，Patchouli 预加载 1405 个 JSON。
- Iris 创建 overworld pipeline。
- TFC Agriculture Plus 的 515 方块渲染自检完成。
- 日志最后出现 `Game took 30.467 seconds to start`，没有 `Stopping!`、`Crash report` 或主线程致命异常。

因此，之前看到的 `overlays` 元数据错误可以确认是资源包格式问题，但在本次日志中它没有阻止资源重载完成，不能单独认定为客户端退出的唯一原因。认证域名、Realms、Xaero 和 NeoForge 在线版本检查失败同样没有形成客户端崩溃堆栈。

当前更准确的结论是：模组已经启动到客户端资源完成阶段；自动化运行器没有稳定保留或枚举该窗口，导致无法继续执行 GUI 测试。需要在 PCL 中直接启动一次，或让启动脚本在独立桌面会话中保持进程，再判断是否能稳定停在主菜单。

## 四、当前阻断证据

日志在客户端初始化期间出现：

```text
Couldn't load overlays metadata
JsonParseException: No key directory in MapLike[{"formats":{"min_inclusive":1,"max_inclusive":100}}]
```

随后资源管理器开始重载，客户端进程退出。日志同时有认证域名解析失败和 NeoForge 在线版本检查的 loopback 连接失败；这些属于当前自动化环境的网络/权限限制，不能作为 K1 功能失败的证据。

该错误指向某个资源包的 `pack.mcmeta` overlays 元数据格式，不足以证明六类厨具代码有问题。应先在 PCL 实例的资源包目录中定位包含 `formats` 但缺少 `directory` 的 overlays 配置，修正或暂时禁用该资源包，再重新执行 A01–A05。

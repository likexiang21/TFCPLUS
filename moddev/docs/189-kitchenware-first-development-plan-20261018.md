# 额外厨具系统优先开发计划（2026-10-18）

## 一、优先级调整

用户已将开发记录中的额外厨具系统提升为下一阶段首要目标。原计划中的普通作物 A1 暂缓，A0 只保留为厨具施工前的最小台账核对，不再先做全量作物审计。

本计划覆盖开发记录中原先被遗漏的功能厨房方块、加工设备、可放置食物和分餐系统。它们属于 B 模组的独立内容，使用 TFC/Firmalife 的公开接口和配方类型，但不直接复制 Extra Delight、Firmalife 或其它示例模组的代码、JSON、贴图和模型。

## 二、厨具系统的三层范围

### 1. 厨房家具与储物层

首批建立厨房空间骨架：

- 橱柜台面：下方储物，上方作为可放置和操作的工作面；
- 半高柜：纯储物；
- 水槽柜：清洗与储物；
- 香料架/调料柜：调料存储和可视化取用；
- 食品展示柜：展示、取用和后续保鲜接口；
- 果盘/糖果碗：小件食品展示和取用；
- 罐展示架、野餐篮、巧克力盒和巧克力火锅：列入后续家具与摆盘批次；
- 花环等纯装饰方块不列入功能厨具首批。

材质规则：

- 木制家具按当前整合包的 34 种 TFC/AFC 木材展开注册、模型和语言；
- 需要石材台面的家具按 TFC 21 种岩石展开；
- 材质贴图优先复用 TFC/AFC 已公开材质引用，新增家具形状和金属细节由本项目独立制作；
- 方块状态数量遵守既有上限，不用状态值承载库存、进度或保鲜数据。

### 2. 厨房加工设备层

按工作区记录的 18 台设备与 `in_world` 配方类型分批推进：

**首批 P0/P1：**

- 干燥架范式继续作为容器和批处理基准；
- 蒸发浓缩器；
- 面团成型台；
- 熔化锅；
- 炒锅；
- 香料架/调料柜；
- `in_world` 世界内加工入口。

**第二批 P1/P2：**

- 熟成架；
- 保冷设施；
- 油料压榨机；
- 研钵；
- 大餐方块；
- 漏斗/龙头；
- 温室、地窖、灌溉和育秧设备的厨房相关接口。

**后续 P2：**

- 菌包设备；
- 养蚕架相关的厨房后处理接口；
- 动力磨、动力榨油机和动力脱粒机。

TFC/Firmalife 已有的锅、桶、烤箱、发酵桶、织机、混合碗和装罐站优先复用，不重复建造同功能设备。

### 3. 可放置食物与分餐层

加工完成后不能只输出手持物品，优先补齐可放置、可切分、可取用的食品：

- 整派；
- 整蛋糕；
- 奶酪块；
- 黄油块；
- 糖块；
- 果冻块；
- 大餐锅；
- 熟食拼盘；
- 腌渍坛；
- 挂晒串。

这些方块使用统一的 TFC 容器接口和独立方块实体保存剩余份数、食物组件及新鲜度。切分或取用必须是原子操作，失败时保留原料、工具耐久和剩余份数。

## 三、实际施工批次

### K0：厨具台账与接口冻结

先建立以下台账，完成后才能写功能代码：

- 方块、方块实体、菜单、屏幕、渲染器和注册 ID；
- 每个设备的输入、输出、容器、工具、时间和失败处理；
- 34 种木材与 21 种岩石的材质展开表；
- 每个食品方块的份数、取用方式、腐烂和保存数据；
- JEI、Patchouli、创造栏、掉落和旧存档兼容入口；
- 与 TFC/Firmalife 已有设备的复用关系，避免重复造轮子。

K0 不修改游戏功能，只生成台账、接口清单和静态门禁。

### K1：厨房骨架首批

顺序固定为：

1. 橱柜台面；
2. 半高柜；
3. 水槽柜；
4. 香料架/调料柜；
5. 食品展示柜；
6. 果盘/糖果碗。

每个存储方块必须：

- 使用 `InventoryBlockEntity` 或 `TickableInventoryBlockEntity`；
- 通过 TFC 标准能力暴露自动化接口；
- 具备满槽、错误输入、取出、破坏、爆炸/活塞替换、区块重载和同步处理；
- 不把库存写入 blockstate；
- 有对应的掉落、语言、模型、JEI 和 Patchouli 入口。

### K2：第一个完整烹饪垂直切片

以“调料 → 香料架 → 炒锅 → 可放置熟食/大餐方块”为第一条完整链：

- 先核对现有调味料输入标签和食品组件；
- 炒锅采用独立状态机，保存输入、翻炒次数、时间窗和失败惩罚；
- 炒锅不每 tick 扫描所有物品，只处理有内容且到达检查间隔的方块实体；
- 配方完成后正确继承食品组件、新鲜度和腐坏状态；
- 重复调味、腐烂输入和错误工具都必须原子失败；
- 结果可以进入食品展示柜、果盘或大餐方块。

### K3：面食与可放置食品

- 面团成型台接入 TFC 谷物和现有面粉；
- 熔化锅接入可可、糖和后续糖果；
- 统一制作整派、整蛋糕、奶酪块、黄油块和果冻块；
- 每个整块食品提供切分/取用操作，并保存剩余份数；
- JEI 显示从原料到成品再到分餐的完整链条。

### K4：储存、保鲜和后续设备

- 在 K1/K2 稳定后实现食品展示柜和保冷设施的保鲜规则；
- 再实现熟成架的时间与温度分档；
- 油料压榨机只扩展油料作物，不重写 TFC 已有橄榄油/菜籽油流程；
- 漏斗、龙头、自动化和动力设备必须建立在已验证的 TFC 容器能力之上。

## 四、设计与实现红线

- 不直接照抄 Extra Delight、Firmalife、示例模组或反编译业务代码；只参考公开行为、接口和数据字段。
- 所有能放物品的方块统一使用 TFC 容器接口；菜单、能力、同步和破坏掉落走同一套契约。
- 不用 blockstate 保存库存、食品份数、腐烂进度或加工时间。
- 不新增与 TFC/Firmalife 重复的基础物品、锅、桶、烤箱、发酵桶和织机。
- 不把静态门禁、资源解析或离线构建写成实机通过；实机仍由用户统一验收。
- 不修改已经由用户确认正常的养蚕、草莓、可可、封窑、案板、干燥架和木工主流程，除非厨具接口确实发现兼容缺陷。

## 五、统一完成标准

每个 K 批次必须同时具备：

1. 独立设计记录和来源/许可说明；
2. 注册、方块实体、菜单、能力、同步、掉落和资源完整；
3. 配方、食品组件、腐烂、新鲜度、工具耐久和容器返还完整；
4. JEI、Patchouli、创造栏和语言文件完整；
5. 静态门禁、资源解析和离线构建通过；
6. 构建 JAR、部署 JAR 哈希和备份位置记录；
7. 实机项目逐项标记“通过 / 失败 / 待验证 / 暂跳过”。

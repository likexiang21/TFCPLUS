# AR2-E：剩余蔬菜、调味及茶咖啡收获物用途

日期：2026-10-25。预期复杂度5/5，实际约4/5。完成当前范围的审查、数据修复、静态检查、离线构建及成对部署；全部新实机项目仍待用户确认。没有启动游戏、运行单元测试、生成PCL整合包或提前开展全局改名。

## 一、52项审查结论

依据当前87作物manifest，扣除前片27种谷物/豆类/油料、6种材料作物、3种整瓜和草莓，剩余50种作物。本批逐一核对其食品定义、普通/野生采收及盆栽的产物ID、公共分类和已有B配方直接引用。另核茶叶、咖啡豆的物品注册、灌木/枝段采收连接和盆栽产物。

这50种收获物均已有食品数据及c:foods/vegetable分类，能够成为原生汤、沙拉、三明治和高档绿料候选。没有独立专用配方不等于没有用途。根茎提供谷物营养也不自动意味着应改为谷物分类；本批没有擅自重配芋头、芡实等的营养、腐烂或分类。

茶叶和咖啡豆现有食品定义允许食用，但没有茶/咖啡饮品加工链。当前依赖TFC、Firmalife及AFC中未发现可直接接用的相应食品加工入口；TFC的labrador_tea/blue_ginger是植物，不能凭名称当作可饮用茶或项目生姜。AFC的teak也不是tea。完整杀青/炒制/冲泡或烘焙/研磨/冲泡继续保留后续，不伪称已完成。

## 二、实际修复

### 三种案板产物恢复原生食材用途

现有姜片、姜黄片、白菜丝有蔬菜食品营养、可直接食用，案板也使用copy_food，但没有公共蔬菜分类。结果是原料可按蔬菜做菜，切完后的物品却不能沿用这些原生入口。

B新增一份data/c/tags/item/foods/vegetable.json，replace:false，仅加入这三种已有物品。它们现在能成为原生汤、沙拉、三明治、高档绿料的候选。按原生配方、设备及食品规则使用；实际界面发现、腐烂拒绝和放入行为仍待实机，不能用静态标签检查代替验收。

不改案板配方：1份姜→2片，1份姜黄→2片，1份白菜→3份白菜丝；原有copy_food、刀具消耗、板耐久、容器逻辑保留。没有另造食材或额外干燥物品，也不恢复已停用的干姜、干姜黄、干白菜丝。

### 茶叶、咖啡豆接入基础堆肥

A既有低档绿料追加标签保留啤酒花，加入tfcfarmingplus:food/tea_leaf和food/coffee_bean，共3项。仍replace:false，生成模板同步。没有把鲜茶叶/生咖啡豆加入蔬菜或水果分类。

材料审查工具原来将整个共享低档绿料标签锁死为仅啤酒花，现改为检查它负责的啤酒花成员、追加语义和无移除；新审查工具负责完整三项成员约束，既不误报新增用途，也不放任成员丢失。

### 现有香料流程保护

姜、姜黄已有石臼磨粉：一份得一份，敲击4次。MortarRecipe拒绝腐烂并调用TFC updateFoodFromPrevious，当前静态核对未发现本批必须改写的证据。

现有合成格调味配方以原汤为主输入，copy_input后添加seasoned特性，拒绝腐烂汤、腐烂香料和已调味汤；不生成新的“调味汤物品”。本批保持该配方、原汤动态食品信息和炒锅现有流程。没有把辣椒、紫苏等一律当作已实现的新香料配方。

### 手册与维护工具

中英文intro保留原六页和全部锚点，分别追加蔬菜与调味、茶叶与咖啡豆两页。说明真实操作及尚未开放的饮品链。对应生成模板同步；手册总页数1382。原有灌木日历、模型、气候和采收规则不改。

新增verify-vegetable-beverage-processing.ps1，只读核对52项收获物、3种预处理食材及姜/姜黄调味接线，生成自然语言用途表，所有RuntimeVerified:false。新审查及完整覆盖台账检查均加入B构建入口。

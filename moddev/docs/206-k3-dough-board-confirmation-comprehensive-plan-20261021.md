# K3 面团案板确认加工功能全面开发计划（2026-10-21）

## 1. 目标与范围

本计划把“面团放上案板后按压、揉捏，再由潜行+右键确认产物”的完整功能拆成可施工、可编译、可实机验收的阶段。目标是让原版谷物面团、蛋糕面团和后续蛋糕/烘焙产物统一使用现有 TFC 案板，同时保留案板当前的切割、分片、原木处理和容器能力。

本阶段遵守项目既有要求：所有可放置物品继续使用 TFC 的容器方块实体接口；代码按本项目结构独立实现，不直接照抄示例模组；原版工作台配方暂时保留；熔化锅由原版方块替代并从 B 的玩家入口下线。

## 2. 当前基线与风险

当前 `CuttingBoardBlockEntity` 已继承 TFC `InventoryBlockEntity<ItemStackHandler>`，有一个可见物品槽、耐久字段、保存/读档和自动化物品能力。它还没有按压次数、揉捏次数或确认状态。

当前 `CuttingBoardInteractions` 的右键分支顺序是：空手取出板上物品；刀具查找切割配方并处理；其他持物放到案板。这个顺序会与新的空手右键揉捏和潜行+右键确认冲突，必须改成显式状态分派，不能只在现有方法中增加一个条件。

当前项目已有 `CuttingBoardRecipe`，适合继续承载刀具类特殊加工；旧 `DoughRecipe` 和面团成型台链属于旧入口，应在旧系统下线阶段移除玩家入口，避免同一面团同时出现两套加工方式。

主要风险有四个：

- 左键既是 Minecraft 的挖掘事件，又是用户指定的按压动作，必须只在“案板上是受支持面团且主手为空”时拦截。
- 空手普通右键、空手潜行+右键、空手取回之间必须有稳定优先级，否则确认会被误判为揉捏或取回。
- 按压/揉捏计数必须跟随方块实体保存和同步，不能放进 blockstate，也不能让客户端和服务端各执行一次。
- 三次按压披萨与四次按压两次揉捏烤馕存在路径重叠，必须由确认动作解决，不能在第三次按压时自动消耗面团。

## 3. 固定玩家流程

### 3.1 放置面团

玩家手持受支持面团对案板右键：

1. 服务端确认案板槽为空、输入属于受支持面团且未腐烂。
2. 使用现有 TFC 容器槽放入一份面团，非创造模式扣除手中一份。
3. 将按压次数和揉捏次数初始化为 0。
4. 向玩家发送可翻译提示：`左键按压面团，右键揉捏面团，潜行+右键确认产物`。

受支持输入包括六种原版粗面团、六种原版酵种面团和 B 的蛋糕面团。锯末面团保持已有锯末面包兼容路线，不自动获得本批新的普通面团产物。

### 3.2 按压、揉捏和确认

- 空手普通左键案板：按压次数加一。
- 空手普通右键案板：揉捏次数加一。
- 空手潜行+右键案板：进入确认流程，不增加揉捏次数。
- 达到某条配方次数只表示“可确认”，最后一次按压或揉捏不能自动生成产物。
- 确认时存在匹配配方：生成产物、继承需要继承的 TFC 食品数据、清空案板物品和计数。
- 确认时没有匹配配方：显示精确文本 `面团尚未成型`，不消耗面团、不清零计数。

推荐将“加工中面团取回”定义为独立的空手潜行+左键。该手势优先级高于按压，仅在玩家潜行、空手、案板上是受支持面团且没有需要确认的特殊右键动作时取回面团；普通左键仍然按压。若后续改用其他取回方式，只能修改取回分支，不能重新占用潜行+右键。

### 3.3 特殊持物加工

玩家手持物品时不进入空手按压/揉捏分支：

- 小刀继续使用 `CuttingBoardRecipe` 或专用面团刀具规则。
- 蛋糕坯使用装有超过 100 mB 奶油的液体容器时，消耗 100 mB 并生成奶油蛋糕。
- 蛋糕坯使用 `firmalife:foods/chocolate_blends` 标签物品时，消耗一份并生成巧克力蛋糕。
- 无法匹配特殊处理时保留现有失败提示和案板内容。

特殊持物加工不会绕过计数确认规则：只有明确设计为刀具/液体/巧克力糊的操作才能在右键时执行。

## 4. 案板状态设计

### 4.1 方块实体字段

在 `CuttingBoardBlockEntity` 增加以下持久化字段：

- `press_count`：按压次数，非负整数并设置合理上限。
- `knead_count`：揉捏次数，非负整数并设置合理上限。
- `processing_version`：状态数据版本，用于后续存档迁移。

不增加新的方块状态属性。原有 `uses_left` 和一个槽位继续由 TFC 容器接口负责。

### 4.2 状态方法

提供集中式方法，避免交互类直接修改字段：

- `isDoughProcessing()`：判断槽内是否为受支持面团。
- `incrementPress()`、`incrementKnead()`：服务端递增并同步。
- `clearDoughProgress()`：清空计数。
- `matchesProgress()`：根据当前输入和两个计数返回唯一的候选产物。
- `confirmDough()`：原子完成匹配、产出、清空和耐久处理。
- `takeDoughForPlayer()`：只处理独立取回动作，并清空计数。

所有修改都调用 `setChanged`/TFC 同步路径。客户端只读取同步后的计数用于提示或渲染，不执行产出和消耗。

### 4.3 保存、读档和异常路径

保存 `press_count`、`knead_count` 和版本号；旧存档没有这些字段时按 0 处理。以下情况必须清零：

- 面团确认成功。
- 面团被手动取回。
- 案板被破坏、替换或爆炸移除。
- 自动化能力抽取面团。
- 输入被其他物品替换。
- 读取到不受支持的旧计数版本。

不得让下一份面团继承上一份面团的加工次数。

## 5. 交互分派顺序

右键案板的服务端分派顺序固定为：

1. 先读取方块实体、主手/副手、潜行状态和板上物品。
2. 板上是受支持面团且主手为空：潜行执行确认，普通右键揉捏。
3. 板上是受支持面团且玩家使用独立取回手势：取回并清零。
4. 主手是小刀、奶油容器或巧克力糊：执行对应特殊加工。
5. 板上为空且手持受支持物品：放置一份并发送操作提示。
6. 板上是普通非面团物品且空手右键：保留原有取回行为。
7. 其他情况：保留现有占用、空板或无配方提示。

左键事件只处理两种情况：

- 潜行、空手、板上受支持面团：执行独立取回。
- 非潜行、空手、板上受支持面团：增加按压并取消本次挖掘。

没有面团、手中有物品或目标不是案板时，左键必须继续遵循 Minecraft 原有挖掘行为。

## 6. 配方与产物实现

### 6.1 案板计数配方

建议新增独立的面团案板配方数据结构，字段至少包括：输入面团 Ingredient、按压次数、揉捏次数、输出提供器、输出数量、食品数据策略和显示名称。它与现有刀具 `CuttingBoardRecipe` 分开，避免把按压次数硬编码到刀具配方。

固定计数如下：

| 输入 | 按压 | 揉捏 | 确认产物 |
|---|---:|---:|---|
| 蛋糕面团 | 3 | 3 | 未烤制蛋糕坯 |
| 蛋糕面团 | 2 | 1 | 未烤制甜煎饼 ×2 |
| 普通谷物面团 | 4 | 2 | 对应未烤制烤馕 |
| 普通谷物面团 | 3 | 0 | 未烤制披萨饼 |

所有表格结果都在空手潜行+右键确认时生成。蛋糕面团不参与普通披萨规则。

### 6.2 刀具产物

- 未烤制蛋糕坯 + 任意小刀 → 未烤制小蛋糕 ×4。
- 蛋糕面团 + 任意小刀 → 生面圈 ×8。
- 普通谷物面团揉捏三次后 + 任意小刀 → 对应未烤制小圆面包 ×4。
- 零计数生面团 + 任意小刀 → 面条。

刀具成功后扣耐久，失败不扣耐久；输出使用 TFC 食品组件策略继承输入新鲜度，避免生成无日期或异常保质期物品。

### 6.3 烤炉阶段

烤炉配方使用 Firmalife 既有烤炉类型或项目已经验证的烤炉数据格式：

- 蛋糕坯、小蛋糕、甜煎饼：达到“热”后继续 1200 tick。
- 烤馕：达到“热”后继续 2400 tick，并设置初始保质期五个月零天。
- 小圆面包：达到“热”后继续 600 tick。

实现前先从当前 Firmalife 资源核对温度字段和时间字段，不能凭空创建新温度单位。

## 7. 旧链下线与新入口

在案板状态机稳定后处理旧内容：

- 面团成型台、方块实体、交互、旧 DoughRecipe、JEI 分类和 Patchouli 页面下线。
- 通用自定义面团不再出现在创造栏、JEI、配方和手册中。
- 熔化锅、MeltingRecipe、专用 JEI 分类、催化剂和自定义巧克力糊配方下线，改读 Firmalife 原版巧克力糊标签。
- 自定义黄油片下线，整黄油分餐直接输出 `firmalife:food/butter`。

首个施工版本保留必要的兼容注册以保护旧存档，但所有玩家入口、配方和展示入口都必须移除；确认旧存档迁移后再决定是否删除注册 ID。

## 8. 客户端显示、JEI 与手册

- 放置提示和失败提示使用语言键：中文分别为两句固定文本。
- 案板上的物品继续使用现有直接渲染器；计数不写进模型状态。
- JEI 增加按压、揉捏、潜行+右键确认说明，刀具操作显示刀具条件。
- 搅拌碗配方继续显示在 Firmalife 原版分类中。
- Patchouli 按“搅拌碗 → 案板加工 → 确认 → 烤炉/装饰”重写流程。
- 创造栏、JEI 和手册清理面团成型台、熔化锅、通用面团和黄油片的旧入口。

## 9. 分阶段施工顺序

### 阶段 0：冻结数据与兼容策略

核对 Firmalife 配方格式、六种面团实际 ID、刀具标签、奶油容器能力、巧克力糊标签和旧存档处理方式；确认 `潜行+左键取回` 作为建议的独立取回手势。

### 阶段 1：案板状态与交互骨架

只改案板方块实体和交互，不接入全部产物。完成计数字段、NBT、同步、左键按压、普通右键揉捏、潜行+右键确认入口、取回清零和原有非面团行为兼容。

### 阶段 2：蛋糕面团最小闭环

接入蛋糕面团识别、3/3 蛋糕坯和 2/1 甜煎饼两个计数配方，完成有效确认、无效提示、计数清零和读档恢复。

### 阶段 3：蛋糕特殊加工

接入刀具切小蛋糕、生面圈、烤炉时间、奶油容器、巧克力糊标签、奶油蛋糕和巧克力蛋糕的可放置分切。

### 阶段 4：普通谷物面团

接入六种谷物的烤馕、披萨、小圆面包和面条；统一食品数据、五个月烤馕保质期和输出新鲜度继承。

### 阶段 5：旧系统下线与资源同步

清理成型台、熔化锅、旧 DoughRecipe、通用面团、黄油片、JEI、Patchouli、创造栏、模型、语言和无效配方引用。

### 阶段 6：构建与实机验收

执行静态门禁、资源解析、离线构建，生成唯一 PCL 测试 JAR；实机验证完成后再更新交接记录和长期开发计划。

## 10. 验收标准

### 基础交互

- 面团放置后立即出现完整提示。
- 普通左键只按压，普通右键只揉捏，潜行+右键只确认。
- 无效次数确认显示“面团尚未成型”，面团和计数保持不变。
- 有效确认只产出一次并清空案板状态。
- 潜行+左键取回不被误判为按压，普通左键仍可按压。

### 状态一致性

- 木案板、石案板、原木案板共用同一套计数逻辑。
- 保存/读档后计数准确恢复。
- 破坏、替换、自动化取出、确认成功后计数都归零。
- 客户端不会重复产出，服务端不会漏同步。

### 内容完整性

- 六种谷物面团和蛋糕面团都能走正确入口。
- 披萨、烤馕、蛋糕坯、甜煎饼等计数路线互不抢配方。
- 刀具、奶油、巧克力糊特殊加工不破坏空手确认规则。
- 烤炉时间、食品新鲜度和烤馕五个月保质期符合要求。

### 清理与独立运行

- 移除 TFC Woodworking 后，案板和搅拌碗功能仍可加载。
- 创造栏、JEI、Patchouli 不显示已下线内容。
- PCL_TFC 中只放置一个新 JAR，不混用旧版本。
- 构建日志无新增编译错误、资源解析错误或重复注册错误。

## 11. 交付物

每个阶段结束时记录：改动文件、配方/ID 清单、构建结果、未完成项和实机验证范围。最终交付包括源码、资源、唯一测试 JAR、实机测试清单、README 更新和 HANDOVER 更新。

截至 2026-10-21，本计划只完成方案记录，没有开始代码施工。下一步从阶段 0 的 ID/格式核对开始，然后实施阶段 1 案板状态与交互骨架。

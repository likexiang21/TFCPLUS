# 路径长度审计与 PCL 短路径迁移实例（2026-10-19）

## 审计结果

本轮扫描范围为整个工作区 `D:\TFC农业重置`，共发现 290890 个文件和 16459 个文件夹。

- 文件路径超过 240 个字符：1730 个。
- 文件路径超过 260 个字符：6 个。
- 文件夹路径超过 240 个字符：1 个。
- 路径最长的文件约 274 个字符。

长路径几乎全部来自开发资料，不属于 PCL 启动所需内容：

- `moddev\backups\` 下的历史源码备份和历史构建产物；
- `moddev\src-ref\` 下的 Patchouli 参考工程；
- 历史备份内部再次嵌套 `src\main\java`、`build\classes` 和资源目录；
- 当前源码项目的 `build\classes` 生成文件。

实际运行目录的最长路径小于 200 个字符，`mods`、`config`、`saves`、资源包和着色器本身不是主要问题。PCL 迁移时复制整个开发工作区，才会把这些历史目录一起带入并触发长路径错误。

## 已完成的优化

已生成短路径运行实例：

`D:\TFC农业重置\PCL_TFC`

该目录保留：

- `mods`；
- `config`、`defaultconfigs`、`kubejs`、`data`；
- `resourcepacks`、`shaderpacks`、`assets`、`patchouli_books`；
- `saves`、`xaero`；
- 原实例的启动配置、版本 JAR、版本 JSON 和运行时文件。

该目录没有复制：

- `moddev` 源码、历史备份和构建缓存；
- `.probe`、`.tooling`、`.vscode`；
- 日志、崩溃报告、截图和 `simplebackups`；
- 仅供开发使用的临时提取目录。

这样既保留了 PCL 运行所需内容，也避免改变原开发工作区和历史备份。

## PCL 使用方式

在 PCL 中把下面目录作为实例目录或迁移源目录：

`D:\TFC农业重置\PCL_TFC`

目录内的 `PCL_MIGRATION_README.txt` 也记录了相同说明。继续写代码时使用原工作区；不要在 `PCL_TFC` 运行目录中编辑源码。

## 后续维护

每次重新构建并部署模组后，只需把新的 JAR 更新到 `PCL_TFC\mods`。如果以后需要重新生成整个迁移副本，应继续排除开发归档目录，避免把 `moddev\backups` 和构建缓存复制到 PCL 实例。

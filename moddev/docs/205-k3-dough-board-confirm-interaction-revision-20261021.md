# K3 面团案板确认交互修订记录（2026-10-21）

## 修订目的

根据最新流程要求，统一面团和蛋糕面团在案板上的产物确认方式。所有按压、揉捏配方都必须先达到指定次数，再由玩家使用空手潜行+右键确认；最后一次按压或揉捏本身不直接生成产物。

本次只修改开发规范和交接记录，没有修改 Java、JSON、模型、贴图、语言文件或当前运行 JAR。

## 固定交互

1. 玩家手持受支持的面团对案板右键放置后，案板显示面团，按压和揉捏计数归零，并发送提示：

   `左键按压面团，右键揉捏面团，潜行+右键确认产物`

2. 玩家空手普通左键案板，计数增加一次按压。

3. 玩家空手普通右键案板，计数增加一次揉捏。

4. 玩家空手潜行+右键案板，执行产物确认。该动作不增加揉捏次数。

5. 如果当前面团类型和按压/揉捏次数匹配某一条加工配方，确认后才生成产物，消耗案板上的面团并清空计数。

6. 如果当前次数没有任何对应产物，确认时显示精确文本：

   `面团尚未成型`

   面团和计数都保留，玩家可以继续按压或揉捏。

7. 小刀、奶油容器和巧克力糊仍属于特殊持物加工。它们使用各自的右键分支，不替代空手潜行+右键确认，也不能被误判为普通揉捏。

## 配方冲突处理

- 普通谷物面团三次按压后只保留当前计数。此时空手潜行+右键确认生成披萨；继续按压至四次并揉捏两次后，空手潜行+右键确认生成对应烤馕。
- 蛋糕面团只匹配蛋糕专用次数，不进入普通谷物面团的披萨条件。
- 其他所有按压/揉捏组合统一采用“达到次数后等待确认”的状态机。

## 状态与边界

- 计数保存在案板方块实体持久化数据中，不写入方块状态。
- 确认成功后清除面团和计数；破坏、替换、自动化取出也必须清零。
- 面团取回动作必须另设独立手势，不能占用潜行+右键，因为该手势已经固定为产物确认；施工时需保证取回不会与左键按压冲突。
- 服务端负责计数、确认、消耗和产出，客户端只负责显示提示、动画和同步结果。

## 后续施工门禁

- 代码中不得保留“最后一次按压/揉捏自动产出”的快捷分支。
- 空手潜行+右键必须先判定当前面团、次数和配方，再决定产出或发送“面团尚未成型”。
- 所有新增提示都要有语言键，并在中文语言文件中使用上面两句固定文本。
- 实机验证必须分别覆盖：有效组合确认、无效组合提示、确认后计数清零、继续加工、特殊持物加工和读档后的计数恢复。

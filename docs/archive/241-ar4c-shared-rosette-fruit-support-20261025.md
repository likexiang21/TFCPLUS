# AR4-C：五种共享莲座结果态的高度与承托修复

日期：2026-10-25。预期复杂度5/5，实际5/5。已实现共享结果模型修复、完成五种作物离线对照与静态检查、构建并部署A。全部实机和最终美术验收仍待用户确认，没有启动游戏或运行单元测试。

## 一、需求、根因及范围

本批遵守120号后续要求：结果方块应下调，保留完整宽叶，不因早期方案把方块重新抬高，也不把叶片切成细条。共享模型rosette_age_5_fruiting影响羽衣甘蓝、刺菜蓟、龙舌兰、马齿苋、剑麻五种作物，不能只看其中一种。

原方块位置为[6,10,6]到[10,15,10]，尺寸4×5×4，像顶在叶丛上方。120号曾记录下调到y7..12的意图，但直接降低会让两片位于中央的直立叶穿过方块内部；仅改Y值不满足承托和不穿模要求。

影响严格限制为五种作物的age=5,fruiting=true。其余55个声明状态、所有作物子模型、方块状态、Java、生长/采收/NBT、食品数据、配方和所有PNG均保持原字节。低龄fruiting=true属于兼容声明，本批不把它解释为正常生长阶段。

## 二、采用方案

共享模型只改一份JSON：

1. 果块从y10..15降低到y7..12，x/z仍6..10，仍居中，尺寸、顶面/侧面纹理和全部UV保持。
2. 原八片倾斜叶的坐标、旋转、宽高、UV及贴图槽完整保留。
3. 原两片中央直立叶移到果块外侧，并各补一片同样完整的对侧叶，形成四面承托。每片仍宽8、高10，位于x或z的5.98/10.02平面，距方块表面0.02；没有切窄叶片或重新绘制图片。
4. 元素数11→13：十二片叶和一个方块。旋转后的叶面没有进入果块内部，也没有伸出方块范围。
5. 共享模型的particle改为#0，成熟结果态继承各物种叶片，不再取通用占位纹理；保留AR4-B已修复的子模型接线。其他状态的粒子不在本批改动范围。

这使方块位于叶丛之间，保留可见顶面及部分侧面。本批是形体位置与承托修复，不宣布五种作物的纹理、器官写实程度或全部美术均已合格。

## 三、前后实际查看

在独立预览目录准备四组：修改前、仅降低、降低并外移承托叶、未结果对照。五种作物分别用yaw40和pitch28/5/70查看，共12张三维图、60格；另有一张24份既有纹理对照。13张图全部实际查看，没有只用几何数值代替观看。

看到的结果：修改前五种方块明显高出叶丛，低视角更像顶着方块；只降低后虽然更靠近叶丛，但刺菜蓟、龙舌兰和剑麻等能看到叶片从方块侧面穿出；外移承托叶后，五种方块更嵌入叶丛，顶面和侧面仍能辨认，完整叶片围在四周。未结果对照保持原先轮廓。

采用assets-supported方案，正式源码文件与该已查看候选的字节完全一致。全部图片都只是离线软件渲染，未包含真实玩家视角、地面遮挡、光影或外部资源包的最终效果，不能标作实机通过。

证据目录：moddev/inventory/rosette-fruit-support-20261025。AR4C-before/lower-only/supported/vegetative-p28、p5、p70为三角度对照，AR4C-textures为二维图；顺序均为羽衣甘蓝、刺菜蓟、龙舌兰、马齿苋、剑麻。另存visual-observations、resource-origins及模型列表。

## 四、防回退检查与工具维护

新增audit-rosette-fruit-support.ps1，并接入A的verify。它检查五种作物60个声明状态、共享模型仅被五个成熟结果子模型引用、果块位置/尺寸、四片完整承托叶、面方向、合法旋转、纹理和结果态粒子。

为防止“只改高度”的回归，独立实现旋转后叶片四边形与果块内部的裁剪相交检查：使用实际旋转坐标，不以未旋转包围盒判断；排除仅接触边界和退化交线。该检查是防回归辅助，不能替代离线或实机美术观察。采用方案穿入内部叶片为0。

旧模型在新契约下有8项不满足，其中含结构、高度、承托及四种结果态通用粒子约束；不是8个独立程序故障。隔离的“仅降低”副本确实检出第8、9号两片中央叶穿模，证明检查没有仅因高度正确而放行。未修改正式素材进行负例验证。

旧gen-rosette-models原完整草稿仍会用早期函数生成高位结果块。现在结果态改为读取当前已复核的源模型，避免另有一套旧参数回退。新增MatureFruitModelOnly安全模式，只把这一份源JSON复制到受限草稿目录，随后退出；不生成其他几何或图片。无Root或指向正式源码的调用仍会在写入前拒绝，互斥安全模式也拒绝混用。

实际运行安全模式仅产生1份JSON，与正式源字节一致；缺省Root和活源Root均拒绝。没有执行完整占位图片生成模式，也没有整体发布旧生成器草稿。全部现有工程命名/结构清理仍保留233号阶段，不提前开展。

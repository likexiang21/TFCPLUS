| 模型 | 违规面数 | 世界尺寸 vs UV |
|---|---|---|
| `leafball_age_2..5` | 24 | 4×3 / 5×4 / 6×5 / 6×6 的面用了 `uv 16×16` |
| `rosette_age_5_fruiting` | 6 | 4×5 的面用了 `uv 16×16` |

| `sunflower_age_3/4/5_top` | 18 | 14.4×16 的面用了 `uv 16×16` |

⇒ **总共 108 个面**。已**全部改成 1:1**，现在审计报 **剩余 0**，
且项目自己的 `check-geom.ps1` 对这 11 个模型全部报 **UVBad = 0**（改前是 6/6/6/6/6 + …）。

修法与依据：
- **立方体面**：UV 取**以贴图中心为锚**、跨度正好等于该面世界尺寸的矩形
  （例：6×6 的顶面 → `uv [5,5,11,11]`；4×3 的侧面 → `uv [6,6,10,9]`）。
- **`sunflower_age_*_top` 的十字板**：原来板宽 14.4（uv 16 ⇒ 横向压 0.9），
  改成**整格宽 0..16** ⇒ `uv 16×16` 天然 1:1（与 vanilla `block/crop` 十字一致，无需改贴图）。
- **花盘**：14 宽 × 12 高 = `uv` 跨度 14×12。
- **`branch_fruit*` 的果实**：按各自真实尺寸取中心矩形（6×6 / 4×5 / 3×4）。

### ⚠️ 顺带又踩到两个 PowerShell 坑（都已记档）
1. **`@()` 里不能写二元表达式**（AGENTS.md 已有此条，我这次**又犯了**）：
   `@($u0,$v0c,$u0+$W,$v0c+$H)` 被解析成 **6 个元素**，UV 直接写坏。
   ✅ 先算到变量 `$u1=$u0+$W` 再放进数组。
2. 🆕 **`[int]` 转换是"四舍六入五成双"，不是截断**：`[int]9.5` → **10**、`[int]6.5` → 6。
   算 `branch_fruit_unripe` 的尺寸时 `from x=6.5, to x=9.5` 被算成 **4 宽**（实际 3），
   导致 16 个面仍然错。✅ **尺寸一律用 `[double]` 相减**，不要先 cast 成 int。

## 二、问题①：叶片必须从中心汇集（几何 v7）

### 2.1 病根
v5 的叶板是**平行偏移的平面**（内层 x/z = 4.5 / 11.5、外层 3 / 13），
它们的**底边各自落在离中心 3~5 格的四个方框上** ⇒ 俯视看就是"四圈方框围着一个盒子"，
而不是"叶子从一点长出来"。用户点名的就是这条。

### 2.2 改法（v7）：改成**径向**叶片，像已被认可的莲座族那样
关键技巧：**让每片叶板的底边正好落在旋转轴上**，于是绕轴倾转后底边不动、
仍然停在中心地面线上 ⇒ **所有叶的基部天然汇集在 (8, 0, 8)**。

每片叶板的写法（与 `rosette_age_*` 同构，`from.z == to.z`，绕 x 轴转；另一轴同理绕 z）：
```json
{"from":[4,0,8],"to":[12,H,8],"rotation":{"angle":±22.5,"axis":"x","origin":[8,0,8]}, ...}
```
- **0° 层**（2 片：x=8 面与 z=8 面）：直立穿透中心的叶 —— 但**高度必须 ≤ 立方体底面（y=8）**，否则会切到球。
- **22.5° 层**（4 片：±22.5 各配 x/z 两轴）：向外倾，**可以长到球顶附近**——
  因为它在 y=8 处已经偏到 `z = 8 + 8·tan22.5 = 11.31` **＞ 球的最大半宽 3**，所以**从球的外侧升起，零相交**。
- **45° 层**（4 片）：更平铺，构成外圈。

高度表（立方体底面统一抬到 **y=8**，顶面 = 11/12/13/14）：

| 龄 | 0° 高 | 22.5° 高（顶/外伸） | 45° 高（顶/外伸） | 立方体 |
|---|---|---|---|---|
| age2 | 4 | 11（10.16 / 4.21） | 7（4.95 / 4.95） | 4×3×4 @ y8..11 |
| age3 | 5 | 12（11.09 / 4.59） | 8（5.66 / 5.66） | 5×4×5 @ y8..12 |
| age4 | 6 | 13（12.01 / 4.97） | 9（6.36 / 6.36） | 6×5×6 @ y8..13 |
| age5 | 8 | 14（12.93 / 5.36） | 10（7.07 / 7.07） | 6×6×6 @ y8..14 |

- **零相交**：0° 层顶 ≤ 8 = 球底；22.5° 层在 y≥8 时横向已在球外（11.31 > 11）；45° 层顶 4.95~7.07 < 8。
- bbox：`X/Z 0.93~15.07`、`Y 0~14`，`inside-block OK`；`faces=26/26`、面类型错配 0。
- 元素数 11（10 片叶 + 1 立方体），比 v5 的 9 个更结构化。

### 2.3 实看（`px/V7B-P70-BIG.png`）
改后俯视：**叶片从球的下方朝外辐射、基部在中心汇成一点**，不再是四圈方框。
与莲座族并排对照（`px/V7-VS-ROSETTE.png`）可见两套几何现在是"同一种语言"。
⚠️ 遗留：叶只分布在 ±x / ±z 四个方位（MC 元素**一个元素只能有一个 rotation**，
无法把"倾斜"与"偏航 45°"叠加），所以方位间隔是 90°而不是 45°；45° 层较宽，俯视铺得还算满。

### 2.4 v8 追加：补上**对角方位**，俯视变成 8 向
⚠️ v7 的叶只分布在 **±x / ±z 四个方位**（MC 一个元素只能有一个 `rotation`，无法把"倾斜"与"偏航 45°"叠加），
俯视是"+"而不是完整星芒。用户要的是「俯视像一株植物」，所以 v8 再补 **2 片对角竖直叶**
（`axis:"y"` 转 ±45°，把原本落在 `z=8` 面的竖直叶偏航到对角平面）：
- 它们**仍然穿过中心**，所以叶基照样汇集在 `(8,0,8)`；
- 高度必须 **≤ 立方体底面 y=8**（对角平面同样会切到立方体），取与 0° 层同高（4/5/6/8）。
- 元素数 11 → **13**（10 片径向 + 2 片对角 + 1 立方体），`faces=30/30`、`inside-block OK`。

**实看**（`px/V8-P70.png`）：俯视变成**8 向星芒**、叶片从球下方向外辐射并在中心汇成一点，
球嵌在莲座正中 —— 这就是「一株植物」的样子。校验复跑全部仍绿（见 §四）。

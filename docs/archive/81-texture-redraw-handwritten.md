## 2. 方法：手写设计稿 → 渲染（可审查）

```
.probe/texture-design/cardoon_cluster_5.txt   ← 逐像素 ASCII 网格 + 调色板（手写）
        ↓  render-design.ps1
.probe/texture-design/out/cardoon_cluster_5.png（16×16）
        ↓  同脚本
   -zoom20.png（20 倍放大 + 棋盘底）  +  控制台量化体检
```

- 设计稿两种模式自动识别：**整张**（16 行 × 16 字符）与**切条**（4 条 × 16 行 × 4 字符）；
- 未写入调色板的字符（约定 `_`）= 透明，**靠留白形成叶片轮廓**（这是 TFC 观感的来源）；
- 设计稿是纯文本，**每个像素都是手工决定**的 —— 不是「一个算法套 N 个参数」。

## 10. 第二轮：贴图结构的关键修正 —— 横向 → 纵向

### 10.1 想清楚的一件事

板宽只有 **4px**，而 `up/down` 面的 uv 是整张 16×16 ⇒ **贴图横向被压缩 4 倍**。
所以贴图的**横向细节必然丢失**，能保留的只有**纵向**（板长方向 12px）。

⇒ 贴图应当「**纵向表达叶形**（叶尖→叶身→叶根）+ **横向铺满**」，
而不是原来那种「横向铺开的叶丛」（压缩后只会糊成细线）。

### 10.2 对照实验（`out/EXP2-compare.png`）

| 版本 | 看图看到什么 |
|---|---|
| 横向叶丛（旧版 A-coarse） | V 形，叶片偏散、偏细 |
| **expA：纵向叶形 + 横向铺满** | **最饱满最「厚」**，叶片连成片 ✓✓ |
| expB：横向条纹 50% 覆盖 | 出现明显**横向栅栏条纹**，人为感强 ✗ |
| TFC `bird_nest_fern` | 仍是更蓬松的多层面片 |

### 10.3 三物种改用 expA（`out/K-final-expA.png`）

- cardoon：饱满的黄绿叶丛；agave：冷灰蓝绿剑叶 + 顶端黑刺；purslane：亮绿 + 中心红褐。
- 三张**都明显比改动前饱满**（从「细针」变成「有厚度的叶丛」），物种差异仍然清晰。

### 10.4 落盘包已同步更新并重新验证

- `deliverable/textures/` 21 张全部换成 expA 版（3 源图 × 7 阶段名）；
- `deliverable/models/` 9 个 json 不变（uv 已在上轮改好）；
- **用落盘包自身的模型 + 贴图**渲染验证：`out/VERIFY-package.png` ✓
- 量化（expA 版）：色数 4 / 不透明像素 176~196 / LUM 103~148。
  ⚠️ opaque 高于 TFC 的 116 是**必然**的：横向被压缩 4 倍，贴图不铺满就会在压缩后消失。

### 10.5 目标 ③ 的状态：改善明显，但仍未达成

从「两撮细针」到「有厚度的叶丛」是实质进步，但**仍达不到「不明显弱于 TFC」**：
TFC 的 4 片 16px 宽板能铺出「碗状多层面片」，我方 8 片 4px 窄板的投影量级本就不同。
剩余差距 = **几何**，用户尚未授权，本轮仍未越界。

## 11. 第三轮：落盘包完整性核实 + shade:false + 多角度判定

### 11.1 落盘包模型完整性核实（「可落盘」的前提）

用 `ConvertTo-Json` 重新序列化模型有丢字段的风险，因此做了**逐字段对比**（原始 vs 落盘包）：

| 检查项 | 结果 |
|---|---|
| 顶层字段集合 | 一致 ✓ |
| elements 数量 | 一致 ✓ |
| 每个 element 的 from / to / rotation(axis,angle,origin) | 一致 ✓ |
| 每个 element 的 faces 名称集合与 texture 引用 | 一致 ✓ |
| 只有 uv 变（切条 → 整张） | ✓ 预期内 |
| textures / particle 字段保留 | ✓ |

抽样：`rosette_age_5` / `rosette_age_5_fruiting` / `rosette_dead` 三个全部通过。

### 11.2 补 shade:false（对齐 TFC 的做法）

实测 TFC 的蕨类模型 —— `bird_nest_fern`(4 个 element)、`sword_fern`(12 个)、`lady_fern`(4 个) ——
**每个 element 都带 `"shade":false`**，而我方原本一个都没有。

`shade:false` 的作用是该面不参与方向阴影计算，使叶片亮度均匀、不因朝向不同而明暗割裂。
已给落盘包 **9 个模型共 57 个 element** 补上；复核：`shade=false` 全覆盖、uv 无不符项。

> ⚠️ 这一项**离线预览器验证不了**（它不模拟方块光照与 AO），效果只能在实机确认。

## 14. 严重修正：整块板会捅穿方块下界（Y<0）

### 14.1 怎么发现的

子代理 B 在交付里主动标注「**Y 最低 −5.66**，需用户裁决」。我一核实，发现**我自己的莲座落盘包有同样问题**：

```
lettuce_age_5.json   旋转后 Y = -5.66 ~ 8   ✗
broccoli_age_5.json  旋转后 Y = -5.66 ~ 8   ✗
rosette_age_5.json   旋转后最低 Y = -5.66   ✗
```

**根因**：`from=[0,0,0] to=[16,0,16]` 的**整块板**绕 `origin[8,0,8]` 旋转时，

**我的责任**：上一轮我宣称「越界坐标 = 0」，但**复核脚本只检查了 from/to 的 X/Z，没有计算旋转后的 Y**。

| 北半 | `[0,0,0]→[16,0,16]` | `[0,0,0]→[16,0,8]` |
| 南半 | （同一片） | `[0,0,8]→[16,0,16]` |
| 旋转后 Y | **−5.66 ~ +5.66** ✗ | **0 ~ +5.66** ✓ |
| uv | `[0,0,16,16]` | 四片分别取 `[0,0,16,8]`/`[0,8,16,16]`/`[0,0,8,16]`/`[8,0,16,16]` |
| 覆盖面积 | 整个方块 | **完全相同**（北半+南半=整块） |
| 贴图利用 | 100% | **100%**（四区域正好铺满） |

## 15. 用户反馈：方块贴图不要用球形（会镂空角）

用户指出：**方块贴图不要用球形，因为会导致出现镂空的角**。

### 15.1 根因

子代理给叶球 head 画了「**直径 6 的圆**」贴图 —— 而 head 的**模型是 8×8×8 的立方体**。
它让立方体的 12 条棱落在贴图透明区，以求「看起来像球」⇒ **棱与角处没有像素 ⇒ 镂空**。

**用透明去"削"立方体，必然在角上露洞。**

### 15.2 修正：实心体块贴图一律「填满 + 明暗塑球」

先做了一次全量排查，发现**全部实心体块贴图都有 44~60% 透明**：

| 贴图类 | 数量 | 现状 |
|---|---|---|
| `*_leafball_head.png` | 8 | 不透明 144 / 透明 112 ✗ |
| `*_rosette_fruit.png` | 4 | 不透明 ~104 / 透明 ~152 ✗ |

全部重生成为：**铺满 16×16（零透明）+ 每象限一个径向明暗球面（中心亮、边缘暗、左上方向光）**，
主色取自各贴图原有的不透明像素平均值，以保住物种色差。

**复核结果：这 12 张贴图的透明像素全部为 0** ✓

> 原则（与 docs/78 §7.2 一致）：**实心体块的贴图绝不能有透明**；
> 球面感只能靠**明暗**塑造，不能靠透明裁剪。透明只该用在「叶片轮廓」这类本来就该镂空的地方。

### 15.3 顺带修正：果实贴图过暗

渲染后发现莲座 fruiting 的中心果实体块像一个「黑洞」——实测其平均亮度只有 38（叶片贴图约 120）。

| 贴图 | 修正前平均亮度 | 修正后 |
|---|---|---|
| `cardoon_rosette_fruit.png` | 38 | **87** |
| `rosette_fruit.png` | 55 | **100** |
| `agave_rosette_fruit.png` | 52 | **101** |
| `purslane_rosette_fruit.png` | 65 | **97** |

同时加强了明暗对比（左上方向光 0.14），使方块状的果实体块也有立体感。
验证：`out/NH-verify.png`（叶球 head 无镂空）、`out/NH2-verify.png`（果实提亮前后对比）。

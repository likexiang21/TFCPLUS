### 🛑🛑 五条新教训（它要求写进 AGENTS.md）
1. 🛑 **块状马赛克的关键是"相邻像素相关性"，不是"用了几个色"** ——
   它第 1 版按**逐行随机 rank** 画 ⇒ 3D 是**满屏雪花噪点**。
   **TFC 的 1px 高频之所以能读成木纹，是因为"相邻行大量重复同一 rank"**。
   ⇒ 正解：**手绘 8×8 块状地图（每格 2×2）+ 手工 1px 接缝**。
2. 🛑 **2×2 全同的暗块在 3D 下读成"黑洞/虫眼"** ⇒ 必须用 **1px 宽的连通线**才读成"裂缝"。

4. ⚠️ **浅色组（LUM>120）低彩度 + 低暗部占比 = 整片"白水泥"** ⇒ 解法是**把最暗档占比提到 15%+ 并加暖**，**不是继续加亮**
   （pecan/jabuticaba/loquat/hazelnut 四张就是靠这条救回来的）。
5. ⚠️ **工具坑**：**重写设计稿会把调色板置 `000000`**，**只对部分物种重跑 fit 会留下纯黑贴图**

### 🛑🛑 两条会影响**所有贴图组**的工具坑（cucurbit-seedling-leaf 实测，已转告后续组）
1. 🛑 **`draw2.ps1 -Out ('<路径>' + $n + '.png')` 这种"表达式拼路径"会静默不落盘** ——
   **统计行照常打印**（说明设计稿被正确解析），**但 PNG 保持旧内容**。
   ⇒ **必须先把路径算到变量**：`$p = Join-Path $dir ($n + '.png')` 然后 `-Out $p`。
   **它为此白跑了 3 轮**（R9/R9B/R10 三张"证据图"实际渲的都是旧贴图）。
2. 🛑 **同一进程里用 `.NET New-Object System.Drawing.Bitmap` 读回刚写入的 PNG，会返回旧像素** ⇒
   **自查"看起来通过了"是假的**。⇒ **收尾核对必须用 `Get-FileHash` 重新编码对照**，或用独立解码器（它改用 Node zlib 手写解码才查出）。
3. 另：`@(@('a','b'),@('c','d'))` 会被 PowerShell 展平；**draw2 抛异常会中断整个 foreach，后面的物种静默不落盘**（表面像"跑完了"）。
📌 **这三条与之前已知的"draw2 行数不足时拒绝写盘"是同一族问题：draw2 的失败可能是静默的。**
⇒ **纪律：任何批量贴图作业的收尾，一律用"设计稿重编码 vs src PNG 比 SHA256"兜底，不要信任渲染出来的样子。**

# AR1-G：莲座作物结果、返种和手册修复交接

日期：2026-10-23。范围：羽衣甘蓝 kale、刺菜蓟 cardoon、龙舌兰 agave、马齿苋 purslane、剑麻 sisal。

## 一、本批结论与验收边界

本批源码与资源修复、静态核对、离线构建和部署已完成，未启动客户端。87种现有作物均已纳入当前范围的深入静态检查，所有实机标记仍为待验证；这不等于农业全部开发完成，也不代表果树、加工用途、自然生成及美术长尾已经逐项验收。

开始前预估复杂度为很高（5/5）；实际约高（4/5）。核对后确认历法、温湿度、养分、寿命和保存可继续使用TFC现有接口，主要改动集中在项目的结果状态、返种数据、说明及防回退检查。

## 二、当前证据与具体修复

### 1. 明确幼苗未结果，并同步两个显示属性

旧构造器没有指定FRUITING默认值。当前Minecraft布尔属性的可能值顺序为true、false，状态定义的any()取第一状态，TFC父构造器只把age设为0，因此旧幼苗可带age=0、fruiting=true。产物掉落还要求age=5，不能据此宣称幼苗已经能掉成熟产物；这是状态初始化错误，而不是已经证实的提前收获漏洞。

现在构造器明确使用age=0、fruiting=false。每次TFC成功完成生长更新后，项目从同一份growth计算age和fruiting，只有growth达到1才结果；旧幼苗遗留的不一致状态在下一次成功更新时得到纠正。只有状态实际变化时才发送方块更新。

不另造计时器。原有显式快速生长调试开关保留，正常启动脚本没有启用该参数；本批也没有启用它。原代码“每阶段约四天”的固定表述已更正，实际时长仍取决于TFC配置、气候、光照、土壤养分及历法。

### 2. 活株侧芽数量与原计划一致

70号原计划要求破坏莲座活株返还一至两份侧芽，但五份实际掉落表都固定一份。现在为其种子条目添加原生uniform数量1～2。侧芽沿用已有seeds/<物种>物品，不新增物品或注册编号。

主产物仍同时要求age=5和fruiting=true，保留原来的TFC产量函数。其他状态破坏只返侧芽；未给莲座添加右键采收。野生植株的掉落和数量规则保留。

### 3. 共享死株保持兼容，返种只在死亡转换成功后发生

既有共享dead_rosette没有物种记录，掉落表为空；项目原设计在死亡瞬间把对应种子返到地面，避免之后破坏共享死株时猜测物种。本批保留这一路径，不换死株ID，不新增NBT。

死亡逻辑增加服务端和当前位置仍为本作物的检查，使用注册时传入的dead供应器；只有成功替换为死株后才弹出一份对应侧芽。重复处理同一死亡位置不再再次返种。死株保留TFC的mature属性，破坏死株仍不重复掉种或主产物。

注意：这不是把死亡返种改为“一至两份”。活株破坏一至两份，死亡瞬间一份，野生规则原值。死亡掉落会受到世界的实体掉落设置及物品消失规则影响，玩家需要及时拾取；本批未将共享死株改造成存物容器。

### 4. 手册展示六龄和结果态

旧手册生成器只识别纯age或age/part键，不能读出age/fruiting的最高龄，导致四种莲座只显示一帧；羽衣甘蓝的历史手工页虽有六帧，却没有明确fruiting属性或展示结果态。文字也把莲座写成普通单格作物。

中英文各修改五个文字页与五个图示页，共20页。现在显示六个未结果叶片阶段，再显示age=5、fruiting=true的完全成熟结果态，共七帧。说明明确种子即侧芽、农田播种、破坏采收、空手右键不采摘以及死亡即时返种。剑麻明确收获纤维、属于材料而非食物。

总页数、物种顺序、锚点、发现规则与物品跳转映射保持原值；本批有意修改的是这五种作物的图示mapping和文字，不能沿用前几批“所有非文字字段未变”的表述。现有PNG、模型和blockstate文件均未修改。

## 三、保存、兼容与独立实现

五种莲座仍绑定项目自己的CROP实体类型，实体工厂用该类型重新创建CropBlockEntity，服务端tick仍调用原生日历更新。growth、yield、expiry、养分、tick、lastGrowthTick继续使用TFC现有读写字段；本批没有发现需要新增自定义保存格式的证据。

旧注册、全部12个age/fruiting状态组合及共享死株的两种mature状态继续保留。不会批量扫描或迁移存档，不删除旧物品。成熟株的结果状态在保存重载后的实际表现仍需用户验证。

实现根据本项目需求独立编写，只核对已安装依赖的接口和行为，不复制反编译业务代码。证据是本机Minecraft与TFC 4.2.11字节码，分别保存在备份内minecraft-state-api.txt和tfc-rosette-api.txt。旧70/71文档中的示例代码只作历史需求依据，不作为代码拷贝来源。

## 七、用户实机清单

建议先用存档副本测试，每种莲座分别准备适合温度、水合度和养分的TFC农田；通过正常种子播种，不用setblock替代种植流程。若加快历法，使用已确认适用于本整合包的测试办法，不把修改显示时间当作TFC生长时间已推进。

| 项目 | 操作 | 预期现象 |
|---|---|---|
| 正常播种 | 各种种子右键农田 | 幼苗出现，未显示中心成熟产物；无实体类型异常 |
| 生长与结果 | 观察正常生长至完全成熟 | 叶片分龄变化；完全成熟后出现中心结果态；无固定每龄四天承诺 |
| 活株采收 | 分别破坏未熟株、成熟结果株 | 活株返1～2份对应侧芽；只有成熟且结果的植株掉主产物，数量仍受TFC产量影响 |
| 右键边界 | 空手右键结果株 | 不采摘；肥料交互仍沿用TFC |
| 死亡返种 | 分别观察未熟及成熟作物在失去适宜环境后死亡 | 原地返1份对应侧芽，变共享死株；之后破坏不再返种或主产物；重复更新不增发 |
| 保存与重载 | 在未熟、结果、死亡三种状态退出世界再进入，并走远卸载再返回 | 进度/状态延续；结果株正常采收；死株不重新发种；不因重载瞬间复活或刷产物 |
| 旧幼苗 | 读取备份旧世界中未成熟莲座，等待一次有效生长更新 | 继续原有生长进度，未熟状态的错误fruiting标志被纠正 |
| 野生采收 | 在已存在野生莲座中分别找成熟/未成熟株并采集 | 原有种子与成熟产物规则保持，无活株返种规则串入野生路径 |
| 手册与用途 | 查看五种作物的中英文文字与轮播图；查看剑麻纤维 | 六龄加结果帧、操作说明清楚；剑麻为材料，不可作为食物食用 |

失败时请保留所测实例的A JAR哈希、latest.log、物种ID、温湿度/养分、实际操作与数量截图；进度异常时可附该坐标方块实体数据。不要先覆盖或删除存档。
